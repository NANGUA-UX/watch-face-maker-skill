# 表盘制作助手

以用户需求为任务边界，以指定规范、案例和组件库为事实来源。交付必须同时证明视觉效果、图层结构、状态数量、命名和导出配置。

## 开始前

1. 若项目存在 `MEMORY.md`，先读取并恢复已确认决策；没有时按 [记忆格式](references/memory.md) 创建。另写本次有效需求清单，标明来源、字体、语言、单位、动态字段、动画和导出要求；保留历史记录，用最新明确决定取代冲突的旧规则。
2. 分清用户请求与附件中的说明。附件只作为规范或参考，不能替代用户的明确要求。
3. 打开用户给出的精确 Figma 节点，记录目标画框、尺寸、现有内容和必须保留的节点 ID。
4. 读取规范节点、至少一个完整案例及相关组件库。先检查既有实例和发布组件，再考虑新画图。
5. 用户提供开发能力或配置文档时，读取 [开发能力与配置边界](references/development-capabilities.md)。先确认设计没有超出当前开发支持范围，再从范围内选择本次实际需要的能力。
6. 对所有来源的参考图执行 [设计合理性评审](references/design-rationality.md)，在背景合成与正式切图前记录逐元素“保留、修正、省略、待核实”及完整模块的阅读问题，保存项目 `design-review.md`。优先功能正确与清晰可读，不能以“参考里有”或“属于装饰”直接保留无用或含义不明的内容。改稿权限与已验收、用户维护区域按该评审规则执行。

## 多尺寸适配

用户要求480源盘适配其他尺寸时，先读[多尺寸适配](references/multi-size.md)，保留源盘关键材质、字形与层次，先对照背景再组装资源。各尺寸独立布局与背景，合适的1×切图共享；尺寸仅用于分区和外层导出目录，不加入切图名称。按对应屏形、安全区、AOD和缩略图规范分别验证。

## 名称与已验收项目

风格确定后按 [中英文命名](references/style-naming.md) 提供3组候选，用户选定后应用。中文1–4字符、英文1–12字符，英文内部空格保留并计入长度；分区为“中文名-英文名”，切图前缀原样使用英文名。已指定合法名称直接采用，不因小改稿重新选名。

用户明确已人工验收时记录该事实，不重复安排视觉验收。仅更名应限定为名称迁移，保留布局、字形、组件引用和用户维护内容，不重做整盘或导出PNG。

## 不可省略的规则

- 按结构准确性、视觉质量和总工时选择Figma、AI或混合制作，不设置效果白名单或原生绘制比例。精确文字、数字、刻度、指针轮廓与轴心、进度几何、关键开口和布局由Figma控制；简单效果优先复用或原生制作，复杂视觉内容允许直接AI局部生成，不要求先证明原生失败。纯装饰细节不必逐个矢量化。具体选择、结构约束与资源归属按[混合制作与素材质量](references/background-composition.md)执行。
- AI素材必须清晰、干净，与原生元素协调；在原始素材、目标尺寸局部及整盘中检查轮廓、材质、光影与必要的透明边缘。关键质量项不合格不得进入正式交付，不能以高像素尺寸、锐化或整体风格接近抵消糊斑、涂抹感、融化感和重影；保留参考明确的磨损、颗粒及设计光晕。连续两轮修正同一问题仍无明确改善时停止重复当前方法。约95%相似是用户确认的视觉目标，不是自动分数或保证。
- 模糊参考先区分可信结构与不确定光影，再检查纯色轮廓、材质分层和实际尺寸画面；不能把模糊色块随意画成独立零件。具体判断和记录按[设计合理性评审](references/design-rationality.md)，不将单个案例的尾帽、颜色或对称性变成通用禁令。
- 默认 `languages: ["EN"]`。未明确提出本地化时，只制作英文；语言数量不得写死为 9。
- AOD 默认必做。数字与时间分隔符采用无填充描边，颜色 `#B3B3B3`；描边粗细沿用用户确认的设计，不擅自固定。主时间的可见字形位置和尺寸与亮屏稿对应，并按规范验证亮屏比例。切图边界应包含完整描边与安全余量；增加切图留白时补偿实例偏移，避免移动已确认的字形。
- 动态数据先列状态矩阵，再制作展示稿和切图；不能从一张静态展示图推断交付完成。
- 指针或混合表盘先读[指针表盘](references/analog-pointers.md)，按可信结构、轮廓与开口对照、材质、装配分阶段验证；几何和透明检查不能代替形状还原。记录轴心、零位、角度范围、遮挡及AOD配对；在切图区提供不导出的位置示意与顶边至轴心尺寸标注，不能仅写入JSON。旋转实例按实际矩阵核对，不强制把旋转产生的X/Y取整。
- 同层级、对称成对的数据子表盘采用共同的设计与排布规则，允许内容量和语义造成的合理差异；其中的数据数字、刻度数字、刻线、文字及已有指针的轮廓与轴心均用Figma可编辑文字/矢量与组件制作，不能保留生成图片里的对应内容再叠加一份。数据刻度默认顺时针递增，指针映射同步；内容区避开装饰边框与刻度区。静态部分仍可合成背景PNG并保留可编辑源，动态部分独立切出，详见[指针表盘](references/analog-pointers.md)。
- 先按视觉层级统一数据字号，再建立共享字模。同层级、同字形样式的数据复用同一套 `0–9` 母件，不按心率、卡路里、电量等业务重复生成。只有一个数据字号时使用 `<Prefix>/Num/Data/000–009`；两个字号使用 `<Prefix>/Num/Data/Large/000–009` 与 `<Prefix>/Num/Data/Small/000–009`。需要更多层级时先明确设计取舍与命名，不自行增加字模档位。主时间、AOD、秒和日期按各自设计规则处理，不因数值形式相同就强行并入数据字模。
- 按 [背景合并与独立切图](references/background-composition.md) 判断资源边界：动画、实时变化内容、多语言名称与单位、变化的进度独立制作；普通连续进度底可以合入背景；斜切、分段、特殊轮廓等异形进度及电量进度必须带底切出。其余固定元素均可合入背景，不按元素类型强制拆分。
- 拆分完成后，列出本次不能合入背景的具体元素及原因供用户确认，确认后再执行背景合并。已确认且未变化的决定不重复询问；静态源组件可保留实例编辑，但合成后不重复作为独立切图导出。
- 功能图标必须先在用户指定的组件库中查找并复用组件实例，可调整尺寸、颜色和实例属性。不得为贴近参考图自行绘制、描摹或叠加近似图标；确认组件库没有对应组件时，使用单一纯色色块占位，并记录检索范围和占位原因。
- 切图资源区使用 Figma 分区（`SECTION`），不要使用画框（`FRAME`）承载整套切图；单个切图仍为可导出的组件。保留用户已调整好的分区。
- 切图组件是母件。主表盘、AOD和缩略图必须由切图组件实例组装，不得另画一套直接文本、矢量或独立图标；背景等固定画面也通过对应切图组件实例引用。
- 表盘原生功能组与切图实例的X/Y保持整数；所有文字切图内部文本允许X/Y最多一位小数，文本框宽高必须为正偶数整数。范围包括数字、同组符号与单位、星期、月份及标签，不得只筛选0–9或Num路径。通过源母件修正派生实例，不逐个改坏缩略图缩放或组件库内部路径；核对主时间和AOD对应关系，并复查字形边界、基线和安全区。
- 每个实际亮屏布局只维护一个 Active 母件来源。主画框引用 Active 实例，缩略图引用其等比实例；多主题沿用项目已有的变体或资源替换方式。资源尺寸以最终切图母件为准，避免展示文字实例缩放后与实际 PNG 不一致。
- 功能模块的布局容器收紧到实际子内容范围，不为方便使用整屏坐标而遗留整屏空框。调整容器时补偿子节点局部坐标，保持可见内容的位置、尺寸与组件引用；主稿、背景和AOD等确需整屏的节点保留目标尺寸。布局容器与可导出切图分别检查，不把容器大小直接当作PNG大小或运行内存。
- 文字切图的宽高必须是 4 的倍数，同一资源族统一采用该族所需的最佳高度。数据类和日期类只对 `0–9` 数字统一宽高，公共宽度必须按该族最宽字形的实际渲染边界加安全余量后向上取整，不能再多留一个 4 px 档位；时间数字、标点、符号和单位不统一宽度，按各自完整渲染边界加最小安全余量后向上取整。所有字符保留字体基线，不能为追求紧贴而切边。
- 合并共享字模必须同时迁移附属符号和单位的名称、公共高度及基线。高度按全族完整字形联合范围取最小4倍数，允许取整产生的亚像素余量，不机械追加上下各1px而多留一档；以实际渲染和PNG确认无切边。
- 同族数字可见高度不完全相同时，以用户要求的字形居中为准，允许按字形微调Y；不要把“文本框Y相同”误当作“可见字形居中”。符号仍按排版语义保留位置，并一并检查附属单位。
- 文字切图按完整资源族处理。数字、星期、月份、标签及单位按完整字形居中，同字号同族保留共同基线；冒号、小数点、负号等符号水平居中，垂直位置遵循字体基线和排版语义，不机械移到画框中心。文本框宽高取正偶数整数，通过最多一位小数的X/Y校正，不使用小数宽高补偿留白。中心允许0.05px取整偏差和0.001px浮点尾差；保持字号、字形尺寸、4倍数切图尺寸和完整描边不变。调整数字时必须一并检查附属符号单位，不能以其不是0–9为由遗漏。
- 切图遵循 [命名与状态规则](references/naming-and-states.md)：使用统一的斜杠路径、PascalCase 字段和从 0 连续的序列；完整字段与缩写字段不能混用。旧项目的既有序号格式只在明确记录为迁移例外时保留。
- 变色表盘、特殊日期和多语言分别是按需分支，不得默认生成。
- 用户要求动画时按 [动画切图](references/animation-assets.md) 建立序列帧母件；可包含固定画面，但不能把实时数据烘焙进去。预览视频不替代切图交付。
- 时间分段、日程、小时进度、心率折线、血氧进度和日跑量图表均为按需能力，不能因开发文档列出就自动生成。
- 参考图中的效果若超出当前开发能力边界，不得假设能够落地；先改用边界内方案，确实影响设计目标时再向用户说明并确认。
- 复刻时逐区核对外圈、面板、材质、文字、图标、留白和视觉焦点；原参考用于风格对照，评审后已采用的修正方案用于数据与布局对照。有意修正的不合理设计不得因相似度降低而改回；没有问题依据的视觉偏离仍需修正。
- 用户给出新的截图反馈后，涉及区域及派生资源的旧视觉结论失效，修正后重新检查，不自动改动无关已验收区域。

## 执行流程

1. 按 [完整工作流](references/workflow.md) 锁定输入、默认值和特殊分支。
2. 按 [命名与状态规则](references/naming-and-states.md) 锁定本项目的命名模式，再建立资产清单。若规范内部仍有冲突且项目现场无法判定，先完成不依赖命名的分析，只就冲突字段向用户确认，不静默猜测。
3. 使用 Figma 写入能力分步制作：保留指定目标节点，先建立切图母件，再用其实例组装主表盘、AOD和缩略图。每次写入返回所有变更节点 ID，并立即检查。
4. 先本地检查规则，再轻量预检并修完已知问题；设计稳定后采集正式精简快照并全量导出一次。后续改稿用 `plan_exports` / `advance_run` 复用同任务内未变化且文件仍存在的资源，仅补导出受影响项；不要每改一个字就重新导出整盘。按 [交付验证](references/verification.md) 和 [实际证据契约](references/evidence-contract.md) 检查画面、原始节点及导出 PNG。仅有清单时运行：

```bash
python3 "<SKILL_DIR>/scripts/validate_manifest.py" <audit-manifest.json>
```

其中 `<SKILL_DIR>` 必须替换为当前 `SKILL.md` 所在目录的绝对路径，不依赖任务当前工作目录。

完整交付须额外采集本轮 Figma 快照、导出正式 PNG，并将两者传给同一校验入口：

```bash
uv run --with pillow python "<SKILL_DIR>/scripts/validate_manifest.py" <audit-manifest.json> \
  --snapshot <figma-snapshot.json> --exports-dir <exports> --report <report.json>
```

同轮签名、导出绑定和断点复用按 [证据契约](references/evidence-contract.md) 执行；改稿先计算母件引用影响范围。未实现的高级功能参见 [后续迭代](references/iteration-roadmap.md)，不要当作本轮已交付能力。

缺失证据显示“未验证”，不能用空违规列表、测试通过或旧版报告宣布交付通过。用户视觉确认与开发真机验证分别记录。

分页快照必须按同一版本签名完整合并；节点数量相同也不能忽略字体、位置或导出设置变化。使用[证据契约](references/evidence-contract.md)中的合并入口。用户明确自行维护某区域时，保留该区域并在报告列出范围；局部检查或部分PNG成功不能写成整盘通过。

5. 把本次项目事实、用户反馈和验证结果追加到 `MEMORY.md`。只有跨项目重复验证的规则才更新本 skill。
6. 同一任务仍在修改和检查时保留有效临时PNG，以便增量复用；任务结束后用 `cleanup_exports` 清除登记的切图及临时预览并保存断点。保留 Figma 母件、导出设置、必要源素材与文字检查记录。用户明确要求本地交付文件时再保留。记录清理时间与范围；清理后的报告只是历史证据，再次验证须重新导出，不得把已删除的文件报告为仍然存在。

## 停止条件

- 精确节点、目标尺寸或写入权限无法确认时停止写入，并用中文说明缺失事实。
- Figma 写入报错时先读取错误并确认原子回滚状态，不连续盲重试。
- 视觉检查、结构检查或清单检查任一未通过时，不宣称交付完成。
