# 背景合并与独立切图

## 素材来源与参考约束

开始制作前记录 `new`、`modify`、`reuse_allowed` 或 `reuse_forbidden` 的来源策略，以及参考图、采用素材、被替代素材的可取得哈希和去向。“全新制作”至少要求最终素材来源符合用户要求；新建 Figma 节点、复制旧图后改名或在旧底图上遮盖，不构成全新素材。用户禁止复用时，复用优先规则失效，旧稿只能参与只读对照。

复刻或保留构图的生成任务先列不变量与允许修改区；人物、姿势、比例、位置、视角、速度线、道路或其他主要场景关系按用户要求锁定。生成工具支持图像输入时必须直接提供实际参考图，不能只把参考转写成文字后重新创造主体与构图。用户的疑问或反问优先视为对当前结果的反馈；只有其明确要求新的分件或构图时才改变制作边界，存在会改变主体的歧义时只确认该关键点。

AI生成范围与最终静态合成范围分别记录。固定文字、图标和刻度可在 Figma 中编辑后合入最终背景，并不代表它们可以出现在AI生成素材中。替换旧图时检查裸背景源、目标尺寸局部和整盘，旧标志、凹槽、刻度、控件和模糊残留必须从源像素移除；在上方叠加新图层遮住不算移除。

## 混合制作方式选择

按来源策略、结构准确性、视觉质量和总工时选择制作方式；总工时包括制作、生成、清理、配准、验证和后续修改。只有来源策略允许时才复用合适的已有组件、效果或清晰素材；方法明确时直接执行，不确定时才做代表性局部小样，不要求Figma与AI都完整试做。不设置效果白名单、原生绘制比例或未经实测的节时百分比。

| 内容与约束 | 制作方式 |
| --- | --- |
| 文字、数字、功能刻度、指针轮廓与轴心、进度几何、关键开口、布局关系 | 默认由Figma可编辑文字、矢量、组件与遮罩精确控制；静态内容同样适用，例外仅限下一行。 |
| 已验收源背景的多尺寸适配，或用户明确选定的一体化背景中的固定标题、数字时标与外圈刻度 | 仅这些已确认内容允许延续与材质整体生成的方式；校对内容、刻度顺序、数量、轴心角度对应及间距，不擅自换成另一套原生字体或标记样式。 |
| 功能图标 | 复用指定组件库；确认缺失时使用单一纯色色块，不以AI绕过此规则。 |
| 少量渐变、阴影、高光等即可表达的效果 | 优先复用或原生制作，按需要选择效果，不遍历所有能力。 |
| 适合以图片表达的复杂视觉内容 | 允许直接AI局部生成；材质、装饰造型、插画、自然景物和特殊效果仅为举例，不限于这些类别，也不只允许叠一层纹理。不要求先证明原生绘制失败。 |
| 同一区域兼有精确结构与复杂视觉内容 | Figma控制关键结构、定位与遮罩，AI制作适合图片表达的部分，纯装饰细节无需逐个矢量化。 |

例如蜂窝仅作为装饰材质时可以整片生成，不要求逐孔绘制；具有指定数量、坐标或穿透关系的结构孔仍由Figma精确控制。除上述已确认的一体化背景例外外，生成范围不得承担文字、数字、功能刻度、功能图标和数据布局，也不能重新决定已确认的关键轮廓、孔位或指针比例。明确要求原生制作的子表盘刻度仍保持可编辑；背景继承不能覆盖这类要求。底图中将被原生重建的对应内容先清除，不能只叠加一份新内容遮盖。允许局部生成不等于授权重新生成整盘或改变主要构图。

用户授权重做背景时，可按目标屏形整体生成连贯背景，不必用小块素材拼贴。仅授权背景重做，不自动放开文字和功能刻度的原生默认；一体化固定内容须符合上表例外。

### 一体化背景的文字与刻度纠错

符合例外的一体化固定文字与刻度仍须逐项校对：错字、缺字、重号、位置与含义不符、时标重叠或拼接痕迹均不能交付。版本尚未选定且修复已获授权时，可针对错误字符或标记局部修复，保持其余内容；需要改换制作方式，应继续匹配源盘字形和材质，不把近似字体当作自动兜底。用户已选定版本时，按下文收尾规则先说明新发现的明确错误及最小修正方案，不自动重生成或叠加文字图层。明确采用原生替换时，先移除对应旧字符，再装入新内容，避免双重显示。实际尺寸检查须能看清目标区域，缩小的桌面全景不能作为局部无缺陷的证据。

在项目 `design-review.md` 记录区域、关键约束、所选方法、选择理由和验证状态；实际试做过才记录结果，直接AI不需要补造原生失败证据。工具暂不可用不等于Figma无法绘制，应如实记录当前访问限制，不据此放弃精确结构约束。

### 用户选定版本后的收尾

用户明确“就用这一版”“直接用上面生成的图”时，记录选定源文件、实际尺寸、哈希及目标母件，停止继续生成、替换风格或追加另一套刻度。选择已明确时不重复确认；仅完成必要的填充、配准、原生数据装配及关联标注同步，保留母件ID和引用。移除本轮被替代的拼接层或重复标记，不能把旧方案叠回已选素材。

用户选择覆盖此前冲突的制作方案，但不等于几何、素材质量、导出或真机项目均已通过。新发现的明确功能错误单独说明并给出最小修正方案，不借视觉改进自行开启新一轮重构；用户明确接受的视觉取舍记录为当前依据。导入优先复用文件内已有图片；确需新图时使用当前工具支持的最小路径，遇参数长度等限制切换可用导入方式，不为导入重生成图片。

### 效果选择与实际验证

选择原生路线时，按参考材质选用有帮助的效果。以下是试做方向，不是固定配方或使用AI前的必做清单；精确几何、字形和关键结构孔洞仍由可编辑矢量、文字及遮罩控制。

| 原生效果 | 表盘中的试做方向 | 重点复核 |
| --- | --- | --- |
| 内阴影、投影 | 凹槽、浮雕、指针与面板的厚度 | 光源方向、接触边缘、阴影裁切，避免产生无依据的拼接感 |
| 图层模糊、背景模糊 | 光晕、柔和反光、磨砂透光 | 区分模糊自身与下方内容，避免模糊文字、刻度和关键轮廓 |
| 噪点 | 细颗粒、喷砂金属 | 颗粒尺度、密度、颜色和混合方式；实际尺寸不能显脏或干扰数据 |
| 纹理 | 表面扰动、粗糙或磨砂质感 | 纹理尺度、作用半径与形状裁切；不是任意碳纤维或拉丝图案的一键替代 |
| 玻璃 | 透明盖板、折射与边缘高光 | 光照、折射、深度、色散和磨砂程度；不把不透明金属误做成玻璃 |
| 着色器 | 常规效果难以表达的程序化纹理或光影 | 先查当前文件或可用库并复用合适项，仍不足再创建；记录来源、版本与参数，不为简单渐变增加复杂实现 |

实际制作前核对当前工具说明及官方效果定义；调用着色器工具时先加载该工具要求的Skill。只对选中的效果做最小局部写入与回读，确认参数、顺序及渲染确实生效；区分“官方支持”“当前工具可访问”“已写入并复核”“导出已验证”。若只能通过界面使用，记录调用路径差异，按现有可用能力操作，不编造API或未经试验宣布受限。相同能力和未变化局部复用本轮证据，不逐个效果反复请求整盘。

保留效果栈的顺序和可编辑参数；检查叠加后是否改变轮廓、产生脏边或损害可读性。背景模糊、玻璃及部分着色器依赖下方内容，不能假定单独透明PNG能保留同样的折射效果：在最终层叠环境和实际导出中核对；固定依赖可按拆分方案一起合成，依赖动态内容时先核对开发能力，不能烘焙实时数据。未要求动画时选静态表现，不因着色器支持运动就新增动画。

复用既有增量导出检查，只验证受影响资源的目标尺寸、透明边界、效果完整性与源画面一致性；回读到效果字段不等于PNG已经正确。生成的着色器属于Figma内可编辑的效果路径，与AI生成位图素材分开记录。无需开发实时重建已合入静态PNG的效果，仍须核对真正动态的行为。

能力依据（2026-09-09核对，实际调用时检查最新定义）：[Figma Effect API](https://developers.figma.com/docs/plugins/api/Effect/)、[查找与使用着色器](https://help.figma.com/hc/en-us/articles/41175721167767-Find-and-use-shaders)。这些文档证明能力定义，不证明本项目已试做或导出通过。

### AI素材质量门槛

生成时明确参考、区域、光向、色彩、需保留的结构及禁止出现的内容；用原生轮廓或遮罩约束需要配准的区域。检查原始素材、目标尺寸局部和整盘效果，不只看缩略图或像素尺寸。

| 检查项 | 合格要求 |
| --- | --- |
| 轮廓与边缘 | 清楚、连贯，无意外重影、毛边、接缝或抠图残留。 |
| 材质细节 | 结构与明暗有依据，无脏污般的糊斑、涂抹感、融化感或杂乱伪细节。 |
| 实际清晰度 | 在最终显示尺寸下清楚；查看原始素材及放大局部时没有明显生成缺陷。缩略图正常不能抵消源图缺陷。 |
| 光影与色彩 | 光向协调、渐变自然，无无依据的灰块、色块或过度锐化光边。 |
| 透明与叠加 | 需要透明的区域有真实alpha；在深浅底和最终背景上无白边、黑边或棋盘格残留，阴影完整。 |
| 与原生元素衔接 | 比例、定位和清晰度协调，不出现原生内容清楚、背景明显糊脏的割裂感。 |

读取真实alpha及其与轮廓、孔洞的对应关系；PNG扩展名、存在alpha通道或棋盘格外观都不能证明透明正确。阴影和设计光晕允许渐变透明，不能要求所有边缘像素完全不透明或仅凭包围框非空判合格。参考中明确存在的磨损、颗粒、柔焦与光晕应保留；不能把生成失真解释成风格，也不为干净抹平已确认的材质。

任一关键质量项不合格，该素材不得进入正式交付；未检查项记录未验证。按实际问题调整生成、修复局部或更换制作方式。连续两轮针对同一问题修正仍无明确改善时，停止重复当前方法，改用其他方法；涉及主要造型、功能或风格取舍时提交具体方案确认。不能以放大或锐化代替细节恢复，也不自报95%相似度。

制作方式与资源归属分别判断：原生效果可以随静态背景合成PNG，AI效果也可能属于独立动态资源。同一材质用于底板可随背景合成，用于旋转指针须随指针独立切出，用于覆盖指针的固定轴帽须保留独立前景。已明确要求的动画或状态素材按对应序列、尺寸和定位规则验证，不把实时数据烘焙进去。切图仍按下文变化行为和层叠关系拆分，不因素材是图片就压进背景，也不因原生绘制就给每个静态效果单独切图。新规则不触发重做已验收或本轮未授权修改的既有位图。

## 材质清晰度排查

先读取Figma实际图片源尺寸、使用倍率、填充裁切与滤镜，再与本地原图及目标尺寸画面对照，区分源图缺陷、错误裁切/缩放与展示倍率问题。高像素尺寸、提高导出倍率或锐化不能证明恢复了细节；核对表圈轮廓、子表盘圆心和边界与原生元素的配准，防止新增重影或结构漂移。对本轮授权修复的糊斑或失真区域，按上述混合制作规则选择修复或替换方法，不机械先做原生。保留原图作为可回退源，保留高质量源素材，避免不必要的反复缩放及有损转存；临时导出与预览按任务结束清理规则处理。报告实际输出像素，不把请求的生成尺寸或5×导出尺寸当成源图真实分辨率。文字、数字、功能刻度等精确结构遵守上文原生默认及已确认的一体化背景例外，不因静态或模糊而扩大生成范围。动态资源按变化行为及层叠关系拆分。

## 背景满幅制作与边缘证据

背景制作按“有效画面→配准→统一裁切→实际PNG边缘”执行。背景母件尺寸正确、图片设为FILL、存在alpha通道，分别只证明对应属性；都不能证明圆内没有源图烘焙的黑白空边。屏幕可见区域按完整屏形检查，文字的safe_margin不能用作背景缩进。

| 源素材 | 制作产物 |
| --- | --- |
| 新生成插画 | 连续矩形画面延续到素材四边，不生成表盘样机、圆外黑白底或展示留白；最终屏形由Figma母件裁切。原参考本来有设计边框或黑色区域时按参考保留，不按颜色删除。 |
| 已有透明圆形素材 | 检查真实alpha与有效画面，按目标屏形配准；已有裁切无法覆盖目标时补充边缘内容。 |
| 已有不透明圆盘或带留白素材 | 核对有效画面区域并保存灰度掩膜（白为有效、黑为圆外填充），不能把整个方形图片当成有效画面。无法区分设计黑色与圆外黑底时保持未验证。 |

新生成提示的背景部分采用这一结构，再填入本盘已确认不变量和清底范围：

> 以输入参考为依据，保留已确认主体的比例、位置、姿势和场景关系。只清理登记的动态UI区域。插画连续延伸至矩形素材四边，不额外生成圆形展示边框、圆外黑白底或留白；最终屏形由Figma裁切。已有圆形参考只在有效画面之外延展场景，不重新生成或放大主体。

修复顺序：先回读母件、图片层、FILL/FIT/CROP、变换与源像素；几何错误先恢复已确认配准。源确实缺内容时，把原图直接输入编辑工具局部补边；保留原有效画面，用Figma遮罩只显示缺口补绘，不能用整图放大、挪动主体或在不透明黑边下面垫色代替修复。补绘结果仍须审看接缝和颜色连续性。

多层补边完成后，在Figma导出合成插画基底并作为母件直属图片使用，保留高质量原图与可编辑补边源组；背景母件ID、主稿和派生实例引用保持不变。固定原生标签或库图标仍可留在背景母件里。这样基底只承担统一裁切，避免素材和容器两次不一致的圆裁。其他复杂裁切先在Figma生成配准后的基底，不猜测其有效区域。

按[背景来源与边缘字段](visual-preflight.md#背景边缘证据)保存来源、有效区域和实际变换；修复任务另保存补边前背景及主体保护掩膜。生成器输出完整外圈、八方向放大局部和深浅底共11图，结论初始未验证。自动覆盖检查与边缘视觉结论分别通过后，才能封存样稿或进入正式交付；旧报告和已验收盘不自动重做。

## 合并与独立切图

这是用户确认的通用规则。判断依据是元素是否需要独立变化，而不是它属于文字、图标还是装饰。示例用于说明规则，不构成自动添加动画、多语言或新功能的需求。

| 元素行为 | 资源处理 |
| --- | --- |
| 有动画效果 | 不能压进单张静态背景；按 [动画切图](animation-assets.md) 制作序列帧。可切局部动画，也可把动画与固定画面合成全幅或局部动画帧。 |
| 内容会随实时数据或状态变化 | 独立切图；例如时间、心率、距离、卡路里、天气和连接状态。 |
| 有多语言需求的名称和单位 | 独立制作对应语言资源；例如 Calories、Distance 及其单位。语言列表按实际需求，不固定数量。 |
| 会变化的进度 | 先核对目标框架和固件是否支持所需原生圆弧/线性连续控件。支持且几何、材质及变化行为可表达时，使用不导出PNG的可编辑原生示意母件；规则连续填充也可按既有切图接口只切前景并把固定底合入背景。分段、特殊轮廓、复杂材质或原生能力不能表达时，连底切出每个状态。业务名称不决定模式，电量也按此顺序判断。 |
| 不属于以上情况的固定元素 | 当前均可以合入背景，包括静态质感、光影、固定刻度、固定图标、固定名称和固定单位。可以合入不等于必须合入。 |

即使只有英文，若单位需要随公制/英制或 ℃/℉ 切换，它仍属于会变化的内容，不能固定进背景。固定单位和会切换的单位应分别判断。

合并前也检查遮挡顺序：必须覆盖动态内容的固定前景（例如指针轴帽）不能合入最底层背景，应保留独立资源。是否需要独立由层叠关系决定，不按某一种图标或表盘作为特例。

制作前逐项记录合并或独立的决定及原因，再建立状态矩阵。拆分完成后，向用户列出本次不能合入背景的具体元素、独立原因及相关条件，等待用户确认后再执行背景合并。清单按实际实现模式区分原生连续控件、规则连续切图和带底状态图，不能按业务名称套用。静态背景在设计阶段完成并导出 PNG，开发不需要实时重建其中的材质、阴影或渐变；开发能力边界主要核对动态行为和设备资源要求。

组件库规则与合并规则同时适用：固定图标即使合入背景，Figma 源设计仍使用指定组件库实例；库中没有时用纯色色块。不要通过栅格化自绘图标绕过组件库规则。

背景作为一个切图母件，主表盘通过其实例引用。背景母件内部可以保留固定文字、矢量和组件库实例，导出时合成一张 PNG，无需为每个固定元素强制增加独立导出项。独立动态资源继续通过各自切图母件的实例组装。

验证时检查动画、实时数据、多语言词条和变化的进度没有被固定进背景；原生连续控件核对可编辑几何、能力来源、无PNG导出及Active实例，规则进度底按本次拆分决定检查，带底状态图核对每个状态。此项需要检查 Figma 源图层及本次模式对应的实际资源；清单数量通过不能替代合并边界检查，原生示意通过也不能代替固件接入与真机验证。

这里的“背景”指单张静态背景。动画帧可以包含固定底、纹理、静态图标等；这些固定内容随每帧一起切出，不等于把动画变成静态。需要独立更新的时间、数据、语言和单位不得烘焙进动画帧。提交拆分清单时注明哪些固定画面随动画帧合成，避免误认为所有动画都必须是透明的小图标。

带底的分段异形进度：000保留所有未激活段，后续状态同时保留已亮段和未亮段，尺寸与轮廓一致。不要将这些底段仅放入背景；迁移回状态切图后移除背景中的重复底段。具体业务名称不决定分类。
