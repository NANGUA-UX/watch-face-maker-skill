# 参考设计合理性评审

用于所有来源的参考设计，包括AI图片、手绘稿、已完成案例和现有表盘。参考分析后、背景合成与正式切图前读取。参考图提供风格和内容线索，不保证其中的文字、数据逻辑或布局正确。

## 判断顺序与改稿权限

优先级：**功能与数据正确 → 清晰可读 → 风格还原 → 细节接近**。先记录需要保留的材质、配色、轮廓、构图特征和整体气质，再判断具体问题；不要借评审把参考改成另一种风格。

- 在当前制作授权内，自动修正有明确依据的拥挤、分组、对齐、间距和错字，完成后简述修改及理由，不逐项请求重复批准。
- 功能增减或含义改变、主要构图重排、风格变化，以及影响已确认特殊设计的修改，先提供具体方案和影响，再请求确认。缺少语义或目标值时先查需求、规范和当前记录，仍无法确定才询问；等待时继续无依赖工作。
- 只读评审、仅更名和已验收/用户维护区域遵循本轮授权，不因发现问题就主动修改。默认修正权限不覆盖用户明确要求保留的设计。
- 偏好不同不等于设计错误。不同层级或明确批准的非对称模块可以采用不同表达；但同层级、对称成对的数据子表盘必须采用一致的设计、身份标识方式与排布，不能用“内容语义不同”跳过一致性检查。统一结构不等于编造缺失单位或新增功能。

## 六方面检查

| 方面 | 观察与验证 | 修改边界 |
|---|---|---|
| 信息含义 | 核对名称、图标、数字、单位是否对应；刻度次序、方向、零位、指针和目标值是否表达同一含义。识别乱码、错字和可能暗示不存在功能的词语。 | 明确错字可修正；看不清的字符不能当作已确认错字。语义不明先核实，不擅自改单位、删除刻度、编造目标值或增加功能。 |
| 信息分组 | 看相关名称/图标、数值、单位是否形成清楚组合；与刻度、邻近数据和装饰是否容易混读。数字内部间距应使多位值被看成一个数。 | 优先调整组内与组间距离、对齐或局部位置；不能把某个字符、某种上下排法固定视为错误。 |
| 层级与一致性 | 同层级数据是否有协调的字号、对齐和阅读顺序；主信息是否突出，辅助信息是否干扰。 | 复用既有字号与字模规则，但不机械统一语义不同的标签和单位，也不要求所有模块都有图标。 |
| 空间与可读性 | 在目标尺寸和缩略图下检查边缘留白、字形辨识、明暗对比和背景纹理干扰；按实际值域检查最长数字、负号、小数和单位切换。 | 不设通用固定间距或美观分数。不为适应一个长值立即缩小全部数据；先在允许区域调整布局。值域不明时标注假设，不能自定最大值。 |
| 动态与遮挡 | 按本次实际功能检查数据长度、进度端点和状态变化；指针表盘复用轴心、扫过范围与AOD检查。检查静态文字、单位、刻度与装饰边框之间的持续阅读冲突。 | 正常转动指针暂时经过数据区可接受，不作为缺陷。检查静态持续重叠和错误层级，不擅自新增隐藏、透明、避让或交互行为。 |
| 开发可实现性 | 先拆静态与动态，再核对已确认的设备能力。材质、阴影等静态效果可以烘焙到背景；需要变化的部分独立实现。 | 复用开发能力及背景拆分规则。未知动态能力标为待核实，不因此删掉可用PNG实现的静态效果，也不假定设备内存或性能数值。 |

检查应覆盖所有已有信息模块，不只处理用户圈出的区域。截图中的选框、批注和编辑器界面不属于表盘设计。

## 模糊细节与局部还原

先列可确认的轮廓、比例、方向、孔洞和连接关系，再列无法确认的反光、阴影、灰边或纹理。清晰度不足可降低质感细节的确定性，不能因此换成通用形状模板。缺乏结构证据的色块，不直接解释为独立零件、尾帽、拼接缝、台阶或凸起；保留可信形状，用少量连贯明暗近似，必要时省略无法确认的细节。明确存在的异材质结构、合理非对称和用户已确认特征应保留，不能反向形成“灰色零件禁止”或“全部对称”的规则。

对复杂、模糊或已被用户指出的区域，按三层对照推进；有问题先修正，再做派生切图：

1. **纯色轮廓**：用临时纯色预览检查针尖、收肩、连接、孔洞、尾部和比例；与可信参考对照，不覆盖正式母件的效果。完成后清理临时预览节点。
2. **材质分层**：恢复效果后检查色块边界是否产生没有依据的拼接或额外结构感。剪影通过不代表此层通过；每个显眼的独立材质块应有参考、设计说明或已确认方案依据。制作方式按[混合制作与素材质量](background-composition.md)选择，不能把涂抹、融化或重影解释成材质，也不能抹掉有依据的磨损与柔光。
3. **实际显示**：查看目标尺寸、放大局部和整盘，分别记录形状、颜色、材质及排布差距，不仅凭整体印象或自动测试宣布通过。

约95%相似是视觉还原目标，不是计算指标或承诺值。没有已约定的量化方法，不报告自拟百分比；用具体差距和“需修正／已复核／待用户确认”描述视觉状态，由用户最终确认。有明显关键轮廓或无依据结构问题时，不能以整体接近为由认定达到目标。原图的不合理设计仍按已确认修正方案处理，不为相似度恢复错误。

在当前制作授权内，普通局部模糊细节采用最小合理解释，不逐点请示。多种解释会明显改变主要造型、风格或功能含义时，提供具体局部方案和影响后确认；不能把所有不确定之处一律删除，也不能无限尝试无方向的小改。

## 评审记录与制作依据

在本项目目录保存 `design-review.md`。采用简短文字和问题表即可，不新增配置协议或审美评分接口。记录：

1. **来源与范围**：原参考标识/路径及可取得的哈希、已有项目记录或当前节点来源、目标尺寸、本轮可修改范围。旧截图和历史快照不能冒充当前Figma状态。
2. **保留特征**：明确哪些风格和已确认功能保持稳定。
3. **逐项问题**：位置、可观察事实、对读取或实现的影响、修改建议、是否需确认、验证方式和当前状态。区分“观察事实”“判断/风险”“待核实”，没有读图或测量证据时不报精确偏差。
4. **修正依据**：保存原参考；记录采用的修改、授权依据及修正后的布局/截图/节点。仍是建议的项目不得写成已修复，待确认项不进入背景合成。
5. **结果与边界**：说明改了哪里、为何修改、如何检查，以及未确认/未验证事项。没有发现问题时也简述已检查的方面和依据，不能靠空问题数组宣布合理。

涉及复杂或模糊效果时，在同一记录中补充区域、关键约束、所选制作方法、选择理由、可信结构、不确定细节及验证状态。实际试做过才写试做结果；直接选择AI无需补造原生失败记录。三层局部对照与AI素材质量门槛分别记录实际结果和未验证项，不以结构或脚本通过替代材质质量；不新增必填配置或相似度分数字段。

后续视觉对照有两个依据：原参考用于核对保留的风格，已采用的修正方案用于核对数据和布局。有意修正的差异不按像素相似度退回原错误；新的反馈只使涉及区域与其派生资源的结论失效，不自动推翻无关已验收内容。

## 与现有验证配合

语义和视觉由读图与场景判断，脚本继续检查可测的几何、字形边界、引用、切图、状态和导出。两类证据分开记录：脚本通过不代表设计合理，评审建议也不代表Figma已经修改。

完成已知修正后再执行正式快照与PNG验证。修改母件或背景时按既有增量计划检查受影响的展示稿、AOD及缩略图，不为了评审先导出整套切图。确需改变独立资源或动态能力时，更新拆分清单并只确认新增或变化的决定。
