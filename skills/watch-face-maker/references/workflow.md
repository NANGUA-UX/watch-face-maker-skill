# 表盘完整工作流

## 输入契约

开始制作前收集并记录：

- 目标 Figma 文件、分组和主画框节点。
- 参考图，以及哪些内容要求复刻、哪些允许适配。
- 尺寸和切图规范节点。
- 至少一个普通完整案例；只有触发特殊需求时才读取变色、特殊日期等案例。
- 图标组件库和可复用组件；记录每个功能图标的组件 key，未找到的图标记录检索范围。
- 开发能力、配置需求和最新命名文档；它们是事实来源，不自动扩大本次制作范围。
- 表盘前缀、主题、语言、单位、时间制式、动态字段和 AOD要求。

默认值：

```json
{
  "languages": ["EN"],
  "themes": ["Default"],
  "aod_required": true,
  "canvas": {"width": 480, "height": 480},
  "units": ["metric", "imperial"]
}
```

默认值必须让位于用户明确要求和当前规范。语言数组可包含任意数量的语言标识；不要补齐固定语言套餐。

## 制作顺序

1. **恢复现场**：读取 `MEMORY.md`、目标节点的结构和截图，确认必须保留的节点 ID。建立本次有效需求清单，记录规则来源和替代关系；历史只追加，不覆盖。
2. **筛选实现能力**：对照 [开发能力与配置边界](development-capabilities.md)，把能力分为本次需要、边界内但未请求、明确排除、文档未覆盖四组。后两组不得直接进入设计；未请求能力不得产生切图或交互热区。

   完成参考分析后，执行 [设计合理性评审](design-rationality.md)：先列保留的风格特征，对元素作出保留、修正、省略、待核实的决定，再按完整模块检查语义、分组、层级、可读性、动态遮挡与实现能力，在项目 `design-review.md` 记录依据并区分事实、风险、建议和已采用修改。不能把含义不明的图形归为装饰后跳过筛选。授权内的明确问题先修正；需要确认的功能/构图/风格变化不进入合成。只读任务仅提交评审。后续步骤使用已采用的修正方案，不能把原参考的错误烘焙进背景。

3. **锁定命名契约**：选择完整字段、缩写字段或旧项目锁定模式；记录命名规范版本、序列格式和仍待确认的词项。同一项目不得混用两套路径。
4. **确定合并边界并建立状态矩阵**：按 [背景合并与独立切图](background-composition.md) 逐元素列出名称、静态或动态、资源归属、独立原因、组件来源。资源归属区分静态背景、局部动画背景、全屏动画背景和独立数据。提交本次不能合入静态背景的具体清单供用户确认，确认前继续不依赖合成的工作；已确认且未变化的决定不重复询问。再列出动态字段、极值、图标状态、进度端点、单位、语言和主题。
5. **建立视觉锚点并选择制作方式**：把参考图归一到目标画框尺寸，记录外圈、各面板、主时间和已有数据区域的中心点、包围盒及相互间距；按评审记录标出有意调整的锚点和理由。按[混合制作与素材质量](background-composition.md)逐区记录关键约束、所选方法、总工时取舍及验证状态，先复用已有资源，方法明确时直接执行，不确定时才做代表性局部小样。精确结构由Figma控制，复杂视觉内容允许直接AI生成，不补造原生失败证据。分别核对轮廓、材质及原始素材／目标尺寸局部／整盘效果，关键质量项不合格不进入正式交付。每轮同尺寸对照分别核对保留风格与修正布局，不把纠错差异改回原稿，也不能只凭肉眼回忆调整。

   指针重建在此阶段完成[可信结构记录和轮廓对照](analog-pointers.md#形状与材质分阶段检查)，通过后再制作材质和正式组装；不要等整盘完成才凭记忆检查针形。

6. **建立切图母件**：先复用目标分区内的切图资源分区（`SECTION`），缺少时创建分区，不创建整套切图的容器画框。按资源族建立背景、数字、标签、单位、图标和状态组件，一次设定名称、状态序号和导出倍率。文字组件先用 `absoluteRenderBounds` 测完整渲染边界，再计算 4 倍数尺寸和同族统一高度；数据类、日期类的 `0–9` 取全族最大字形宽度加左右安全余量，只向上取整一次得到最小公共宽度，时间数字、标点、符号和单位按各自内容收紧宽度。
7. **建立主结构**：保留目标主画框。只在 Active 母件内维护背景、外圈、功能区和时间区的布局，主画框直接引用 Active 实例；各独立资源从切图母件创建实例。
8. **制作亮屏稿**：使用切图组件的实际导出尺寸完成视觉层级和示例数据。最终字号先落实到文字母件，再用 1× 实例排版；不保留一套母件字号和另一套缩放后的展示字号。
9. **制作 AOD**：使用无填充、`#B3B3B3` 描边时间切图实例组装，保留已确认描边粗细和主时间可见位置；把描边范围计入切图安全边界，验证实际PNG及亮屏比例。
10. **制作缩略图**：引用最终亮屏组件实例等比生成，不另画一套可能漂移的版本。
11. **实际验证**：先检查本地清单与目标节点的名称、尺寸、完整文字族和引用关系，完成已知修正及局部视觉核对。设计稳定后用 `profile: "validation"` 采集完整正式快照，再全量导出背景、独立资源、AOD、缩略图及展示图一次；导出前后核对来源签名，未变化时不再完整读取同一快照。修改后使用增量导出计划，只重新生成受影响PNG，其余必须通过资源依赖指纹与实际文件哈希检查才能复用。与当前快照一起校验，输出“通过、失败、未验证、不适用”，问题定位节点或文件。逐区记录字形边界、中心、基线与间距；还原度、组件语义、动画区域合理性和用户验收单独记录。
12. **记录结果**：把项目特例和验证证据追加到项目记忆；可复用结论才进入 skill 参考。

## Figma 写入原则

- 先只读检查，后写入；复杂表盘按背景、外圈、功能区、AOD和切图分批完成。
- 文本修改前加载实际字体；远程组件按发布 key 导入并保留为实例。
- 缩放官方实例使用等比缩放，避免只改外框导致内容裁切。
- 官方库实例先封装为项目切图组件；主表盘、AOD和缩略图再引用项目切图组件实例。修改资源时只改母件。
- 功能图标不得为了还原参考图而自行绘制或在组件库实例上叠加自绘覆盖层。指定组件库中有对应组件时必须使用组件实例；检索确认没有时，只创建一个单一纯色矩形作为占位，并在清单的 `icon_assets.fallback_blocks` 中记录。电池等多状态图标也要逐状态复用组件库资源，不能因状态数量多而改成本地矢量重绘。
- 高细节机械背景按[混合制作与素材质量](background-composition.md)分区选择方法，允许直接生成复杂装饰内容，不重新生成精确结构与数据布局。保留原始高质量源图，源图建议至少达到其实际显示区域的2倍，但像素尺寸不等于清晰度；`1× PNG`是导出设置，不代表上传前缩成1×。避免不必要的反复缩放和有损转存。独立资源按背景合并规则判断，不能把所有图标和单位一律排除在背景外。若用户或参考图要求背景贴边，在母件内等比放大并居中裁切有效源图，不能把源图四周的黑色留白当作有效背景。
- Figma 的 480×480 节点截图只能证明最终设备像素画面，不能证明背景源图清晰度。背景上传后回读原始图片，核对像素尺寸和文件哈希；高倍率展示图不得由 480×480 背景源图直接放大。
- 测文字边界时检查完整祖先链：组件、资源行或资产板的裁切都可能使 `absoluteRenderBounds` 变小。必要时把文字临时克隆到不裁切的测量容器，加载原字体后测量，保存测量来源并清理临时节点。不能把已裁后的边界当作完整字形；对冒号、小数点等标点保留所属族基线，不按自身边界垂直居中，也不套用数字的统一宽度。
- 同族高度由完整字符集合在共同基线下的上下边界计算，数据和日期的公共宽度仅由 0–9 决定；安全余量后向上取整到最小 4 倍数。导出后用 PNG 的透明边界复核，但仅凭裁后 PNG 不能证明源字形完整。
- 修改节点后使涉及的旧快照、导出和视觉确认失效，重新采集受影响证据；合并分页时核对总数、重复 ID、结束标记及采集期间未修改的条件。
- 每次创建或修改都返回节点 ID；每个主要阶段结束后截图。
- 不用“脚本运行成功”代替视觉检查，也不用截图代替状态和导出检查。
- 最新命名文档中的词表若存在相互冲突的全称、缩写或版本号，不进行批量猜测式迁移。先保留旧项目结构，并在清单的 `naming.unresolved_terms` 中记录。

## 按需分支

- 明确要求动画：先按 [动画切图](animation-assets.md) 确定播放条件与局部/全幅裁切范围，再制作逐帧组件及预览；背景拆分阶段就保留动画区域，不能合并后才发现需要拆出。
- `languages` 超过一个值：只为本次已存在且需本地化的字段建立对应资源，不因此新增日期等功能。记录用户语言与导出代码的映射；模糊代码（如 ZH 的简繁选择）须从项目资料确定，不能静默替换。按实际文字检查字体覆盖、阅读方向、连写塑形、组合附标、数字及标点顺序和最长词条，缺少事实的语言标为待确认。
- `color_variants: true`：先锁定主题列表、哪些资源变色、切换方式，再逐主题验证所需状态。复用现有项目的变体或资源替换机制；每个实际布局只维护一个 Active 来源，主稿与缩略图不得复制维护。颜色改变不必复制未变化资源，也不能因为主题开关而新增语言或动画。可学习使用者提供且有权限访问的变色案例；应用前只读确认结构，不把案例主题数量设为默认。
- `special_date: true`：先锁定日期表现、值域、选中与普通态、位置相关切片和与普通字模的替代关系，由实际状态维度推导数量；开关本身不能决定帧数。按使用者提供的特殊日期案例学习拆分方式，验证月末和所有实际选中位置。普通横排日期不进入此分支。
- `time_period: true`、`schedule: true`、`hour_progress: true`、`heart_rate_chart: true`、`blood_oxygen_progress: true`、`weekly_run_chart: true`：只读取对应开发配置并生成实际需要的状态或绘制规格。
