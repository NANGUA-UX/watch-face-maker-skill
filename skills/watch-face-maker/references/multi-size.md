# 多尺寸适配

- AOD指针在每个目标原生尺寸下默认2px、最小2px（已确认更粗的设计保留）；同时回读目标母件与实际显示实例，防止整盘缩放后描边变细。复查描边边界和透明开口，必要时扩大亮屏/AOD配对切图并同步补偿局部轴心、实例和可见标注。

- 每个目标尺寸分别将亮屏与AOD时间字模逐字符配对，同一字符两态的切图宽高必须一致（包括0–9及时间分隔符）。以两态联合渲染边界及至少2px的AOD描边确定公共尺寸；不同目标屏幕可使用各自尺寸，不能仅比对480源盘或当前展示的几个字符。

用户明确一个以上目标尺寸，或要求已有源盘适配其他规格时进入。开始前确认当前用户认可的源稿、源尺寸、全部目标尺寸及屏形；未确认的尺寸不开始写入或导出。先分流：同屏形、同长宽比默认按下节比例派生；屏形或长宽比改变、或用户明确要求重新排版，才走后面的重排路线。源稿不必先取得最新版生产规范通过，已有问题单独报告。当前规范覆盖480×480、466×466、390×390圆屏和390×450圆角方屏；这些只是可选规格，不默认选择480，只生成本次确认的目标。

## 同屏形比例派生

以用户完成的源稿为设计依据，默认缩放其内部元素，不先重排外圈、模块或留白。例如480圆屏到466使用`466/480`，到390使用`390/480`；每个目标直接从同一当前源稿派生，不从上一个目标再次缩放。圆角矩形除屏形及长宽比外还须满足目标圆角与源圆角同比；不一致时报告具体差异，不能静默拉伸。

保留TEXT类型、字体/字重/斜体、字符、配色、素材、效果类型、图层顺序、组件拆分、布局模式与相对排布。先计算位置、尺寸、字号、像素字距、Auto Layout间距/内边距及阴影参数的比例中间值，再按下节落实整数；不能把rescale产生的小数当最终参数。角度、透明度、颜色和业务语义保持。源负间距保持语义并取最近整数，不清零。已有库图标保留来源，已有背景直接派生，不因适配重画或更换材质。

先读回源及依赖母件的当前结构、字体、效果、实例覆盖和签名，按实际ID对应。优先原生`clone()`/`rescale(k)`；已有字模不强制经过新建字模生成器。源TEXT带阴影或旋转不构成转曲、栅格化、换字体或重画的授权。字体无法加载、远程母件不能安全派生、实例覆盖不能保留或API不能证明结果时，停止该资源，报告具体ID和原因，继续独立可做项。

按依赖建立源→目标母件映射，每个目标资源只缩放一次；Active/AOD重新绑定目标母件。正式显示实例须与目标母件保持1×，缩略图按规定单独缩放。不能仅缩小展示实例却交付源尺寸PNG，也不能因源母件看起来仍清晰而在比例派生中保留部分字符原尺寸。重复执行先检查本目标的既有映射与当前签名，相同则复用；有用户改动或映射冲突时先报告，不能再建同名母件或覆盖目标改稿。

### 最小修正与源稿冲突

普通图层及目标母件的X/Y、宽高、字号、描边（包括未启用的默认值及虚线段长/间隔）、圆角、间距/内边距、像素行高/字距及阴影偏移/模糊/扩展使用整数。正字号按`max(1, floor(源字号×比例+0.5))`取最近整数，不要求偶数字号；例如80适配466为78、适配390为65。其他有符号像素量按绝对值四舍五入再恢复符号，避免负间距被清零；可见描边至少1px，AOD至少2px，已确认更粗描边保留。

先把字号及样式参数落到目标原生TEXT，再测完整字形；文本框向上取正偶数，亮屏/AOD逐字符按联合边界取同宽高4倍数切图。文字位置用最近可行整像素，居中误差每轴≤0.5px，另容许0.001机器尾差；不能为追求旧0.05px误差又写回小数。共同基线仍一致，完整边界包含阴影和描边。缩放、内部对齐和外框补偿后，普通布局参数仍须是整数。

仅经真实结构验证的旋转/径向派生坐标与布尔包围框、矢量内部路径和缩略图等比派生可保留必要精度；不是整棵旋转子树豁免，字号、设计线宽和普通框尺寸仍检查。颜色、透明度、矩阵和实际字形墨迹边界不按像素布局取整。缩略图可能把缩放存入实例尺寸而保持单位矩阵，应按Active引用、实际等比尺寸和位置核对，不能仅看矩阵是否含缩放系数。

外框增加透明留白时补偿内部偏移与实例定位，在整像素约束下保持最近可行的字面锚点、共同基线和整数轴心，记录必要偏差。Auto Layout会随外框变化重排；比较补正前后的字形位置、推进宽度和组锚点，不能只凭居中属性宣称保真。无法安全补偿、需要明显移动模块或改变字形比例时，提交具体差异再确认；不清零负间距或用包装框改变阅读关系。

源稿已有负间距、旧命名、旧拆分或其他生产冲突按原状派生并单独列出，不借尺寸任务修复全部旧问题。正式检查仍如实返回失败/未验证，不增加豁免、不伪造生产通过。新发现真实裁切或重叠时给出最小修复方案，不能以保留源稿为由忽略。

资源对照表记录`源节点/母件ID｜目标ID｜比例｜保留项｜尺寸修正前后值与理由｜源已有冲突｜检查状态`；这是原对照表的补充，不新增合同字段。源变化重新读取；旧对照图、PNG和受影响验收结论失效。

### 保真核对

除已有几何/PNG检查外，按源→目标读取实际TEXT、字体、效果、布局与引用；对普通参数比较的是比例值经语义取整后的目标值，不继续要求小数字号或小数间距。新`snapshot.native_pixel_values`与整数位置检查须同时通过。对照源比例画面、实际目标及原生局部，核对可读性、共同基线、轴心和必要偏差；实际显示实例也回读字号/效果，不能只看外框证明1×。源480前后签名不变；生产、用户和固件验收分别记录。

### 原生操作模板

先加载源及依赖TEXT的全部实际字体，再进行修改。下面是单层依赖、源显示实例1×的初始派生片段，尚不是整数化完成稿。变量取自当前盘点；已有目标先核对映射，不重放创建。其余普通参数须按上节全部整数化，重新测量/对齐，再回读校验；不要直接导出这一步的比例中间值。复杂嵌套和源实例已有缩放须单独核实，不能盲套逆比例。

```javascript
// sourceMaster/sourceActive为当前源节点，resourceSection为目标资源分区。
// fonts为源/依赖的真实fontName列表；font加载失败时尚未创建目标。
for (const font of fonts) await figma.loadFontAsync(font);
const k = targetSize / sourceSize;
const sourceTexts = sourceMaster.findAll(n => n.type === 'TEXT');
if (!sourceTexts.every(n => Number.isFinite(n.fontSize))) throw Error('混合字号须按原始分段处理');
const targetMaster = sourceMaster.clone();
resourceSection.appendChild(targetMaster);
targetMaster.rescale(k); // 母件的字号、效果和几何各缩放一次
const targetTexts = targetMaster.findAll(n => n.type === 'TEXT');
for (let i = 0; i < sourceTexts.length; i++) {
  targetTexts[i].fontSize = Math.max(1, Math.floor(sourceTexts[i].fontSize * k + 0.5));
}
const targetActive = sourceActive.clone();
resourceSection.appendChild(targetActive);
targetActive.rescale(k); // 包含实例和源间距，如负间距
const linked = [];
// 本片段的sourceMaster没有嵌套实例，sourceActive只引用该源母件。
for (const instance of targetActive.findAll(n => n.type === 'INSTANCE')) {
  const main = await instance.getMainComponentAsync();
  if (main?.id !== sourceMaster.id) continue;
  instance.swapComponent(targetMaster);
  instance.rescale(1 / k); // 消除clone Active留下的k缩放覆盖
  linked.push(instance.id);
}
return {
  createdNodeIds: [targetMaster.id, ...targetMaster.findAll().map(n => n.id),
    targetActive.id, ...targetActive.findAll().map(n => n.id)],
  mutatedNodeIds: [resourceSection.id], linkedInstanceIds: linked
};
```

实测`clone Active → rescale(k) → swapComponent(已缩放母件)`会保留实例的缩放覆盖，使内部字号/阴影再次缩小。上例的逆比例只消除该次已知覆盖，必须再比较内部TEXT字号、效果、实例宽高和目标母件，保留源实例的字符/颜色覆盖及朝向；失败时停止，不用单改外框掩盖。`createInstance()`默认不带源实例覆盖，不能作为通用替换办法。Auto Layout在修改子实例后可能尚未完成重排，另一次只读调用确认最终位置与边界后，再做最小修正、导出与验收。

## 当前规格与冲突处理

|尺寸|屏形|圆角px|缩略图px|
|---|---|---:|---|
|480×480|circle|240|256×256|
|466×466|circle|233|256×256|
|390×390|circle|195|216×216|
|390×450|rounded_rect|90|240×276|

这是当前规则集，不是所有设备的通用规范。390×450的90px为本次确认值；存在其他规范值时先核对项目当前有效决定，不能自行换成100px。具体规范链接、节点与用户取舍留在私有项目记录。其他设备须先明确屏形、圆角、缩略图和安全区，再扩展规则集与测试。

内容边缘安全距离至少4px，按目标原生像素计算；顶部/底部状态点区域从对应模板读取，记录局部矩形与来源，不能自设统一尺寸。背景与固定外圈按设计贴边，不套用文字安全距离。数字AOD的0–9和时间分隔符采用无填充描边#B3B3B3；每个目标原生尺寸下默认2px、最小2px，保留已确认更粗的设计，不能随整盘缩放降到2px以下。复查目标母件与实际显示实例的描边、完整渲染边界和PNG；扩展切图时保持4倍数尺寸与同族统一高度，补偿实例偏移。亮像素上限按现有10%规则集检查，分母使用实际屏形。

## 决策表与制作顺序

先记录一份资源对照表：`区域/资源族｜源母件ID｜源尺寸及样式｜目标尺寸｜复用/比例派生/新建/重排｜理由｜目标母件ID｜检查状态`。以下资源尺寸取舍适用于重排路线；同屏形比例派生优先执行上节。制作方式与动态拆分分别判断；缩小版本不能把实时内容烘焙进背景。

- 原尺寸在目标中清晰、合适，且字形、颜色、描边、状态语义一致时直接复用。466不保证全部复用，390也不必把所有资源重做。
- 原资源过大、过小或需调整样式时，新建对应规格的可导出组件。正式Active/AOD按1×实例组装；不能只缩放展示实例却交付大PNG。组件库图标仍使用库实例，必要时放入目标尺寸切图母件，不能自行描摹。
- 文字规格调整同时处理数字、符号、单位、星期、月份与标签；先用整数字号测量，再重算4倍数切图边界、公共高度、整像素居中与共同基线。
- 新设计的数值切图组用横向Auto Layout、`itemSpacing=0`，无分散排列或包装留白；已有认可源稿的比例派生保留源排布和同比间距，生产冲突按上节单列。数字切图本身的合规留白保留，字段间距在外层单独设置。
- 每目标只维护一个Active母件，主稿与缩略图引用它；AOD、指针位置示意及动态资源映射分别对应该目标。源盘母件ID、位置和已验收布局不改。

### 屏形变化或授权重排

独立布局不代表重新设计风格。制作前从当前源盘记录关键视觉特征：材质纹理与光向、边框和倒角厚度、主要字形轮廓、模块占位及前后层次。检查完整背景来源，不能只复制可编辑子层而漏掉已合入位图的金属外壳、压边或标题质感。优先复用合适的源素材与组件；需要重构时按混合制作规则选择方法，不用普通网格、细描边或近似字体替代源盘关键特征。

已验收的源480背景若已一体生成固定文字、数字时标与外圈刻度，目标尺寸延续这一方式并保持字形、材质及阅读关系，不默认拆成另一套Figma文字。按[背景规则](background-composition.md)校对这些静态内容；动态内容及明确要求原生制作的子表盘仍独立处理。源素材拼贴出现连续纹理断层或标题裁切时停止拼贴，采用目标屏形的连贯背景生成或重构，不用扩大柔化遮罩掩盖缺字。

圆转方须一并重排外圈数字、主刻度和细刻度，沿目标直边与圆角连续过渡，不能只把数字移到方框而保留圆形刻度圈。数字完整落在对应边框带内，与刻线、金属时标分层留白，特别检查四角附近的数字是否仍悬在内圈、跨越边框或与时标相碰。布局与实际指针轴心及数值顺序共同核对；具体字号、旋转方向、间隔和坐标依据源盘与目标案例，不把单个案例写成所有方屏的固定坐标。

区分刻度带的路径、时标的朝向和读数对应关系。刻度带沿方屏边框，并不意味着每根时标都垂直于所在直边；参考采用向心时标时，保留其对准实际指针轴心的方向，12、3、6、9四个主轴以外的长时标应按对应钟点倾斜，不能批量改成竖直或水平短块。主时标、分钟分度与数字须共同校对位置、顺序、数量和间距，不以沿周长等距代替指针角度映射。合理的切向文字方向或装饰性刻线另按参考判断，不机械把所有元素旋转为同一规则。

用户已选定目标背景时，直接按[选定版本收尾](background-composition.md#用户选定版本后的收尾)完成装配；下述检查不能变成未经请求的重复重构。

先完成目标背景的代表性区域并在实际画布对照，再组装整套资源。对照同时看源盘与目标的完整构图、各自原生尺寸和局部；区分屏形变化必需的重排与非必要的材质、字形和厚度损失。图片尺寸正确、背景铺满、元素齐全不能证明风格保留。裁切复用须排除旧刻度残片，检查拼接边界和纹理尺度；不合格区域继续修复，不靠缩略图掩盖。

466/390圆屏按比例派生后检查标题、数值、单位、状态及最长组合；检查不授予重排权限。只有实际冲突无法通过最小修正消除时，给出具体排布差异并取得确认，不擅自删功能。

390×450背景、边框、纹理和布局须覆盖完整圆角矩形可见区域，并利用上下空间重排。内部圆形模块仍可保留圆形；不能仅放一个居中的390圆盘，也不能非等比拉成椭圆。从可编辑源或高质量素材重新生成目标背景，保留结构与材质层级；按混合制作及AI清晰度规则检查，不反复缩放旧480PNG，不因黑色是设计底色就判定未铺满。

指针复用时局部轴心不变，屏幕轴心与定位按目标重算。新切图尺寸或裁切变化时同步局部轴心、旋转实例、AOD和位置标注；长度、内芯收口、孔洞与轮廓仍按原指针结构对照，不用裁短针尖解决越界。正常转动临时遮挡可接受。进度同步底图、端点和数据映射；已要求的动画重查所有帧的公共裁切区与接缝，不新增动画或全屏序列。

新规格指针缩放后按[轴心与标注规则](analog-pointers.md)完成整数化，不能直接交付比例计算产生的小数局部轴心。先修母件和真实定位再生成标注；旋转矩阵及缩略图派生坐标保留所需精度。

## 分区、名称与文件

Figma v3.0 新项目的总分区保留正式名称 `<EnglishName>/<中文名>（<五位编码>）`，其下按尺寸建立独立SECTION，各切图区仍为SECTION。切图名称及相对导出路径不增加任何尺寸前缀或尺寸字段，例如始终为`SampleFace/Num/Time/000`。共享母件保留原处，其他尺寸引用实例并记录对应ID；新规格可在不同尺寸分区保留相同名称，同目标内不可重名。旧项目原有“中文名-英文名”总分区按 `legacy_locked` 保留。

尺寸只出现在外层目录：`390x450/SampleFace/Num/Time/000.png`。配置中的 `name_en` 保留表盘英文名的单词间空格，`prefix` 使用去掉空格后的连写值。统计与校验键是“目标尺寸＋资源路径”，不能全文件按名称去重或通过新增编号消除冲突。

缩略图按表中容器尺寸等比居中，使用相应屏形与圆角，屏形外为不透明黑底。390×450放入240×276时内容约239.2×276、左右各0.4px，不能强制拉伸到240宽；缩略图派生坐标不受原生功能组整数坐标限制。

## 配置及采集接口

沿用单目标manifest与snapshot，在每个目标的manifest.canvas和snapshot.config.canvas记录相同规格：

```json
{
  "width": 390, "height": 450,
  "shape": "rounded_rect", "corner_radius": 90,
  "safe_margin": 4,
  "source": "本项目已核实的规范与取舍",
  "reserved_regions": [{"x": 180, "y": 4, "width": 30, "height": 12}]
}
```

示例状态点矩形只是接口示意，不是设备默认位置；实际必须读取模板。空数组仅用于有证据确认没有保留区的设备；未知时省略并标未验证。manifest.exports.preview与snapshot.config.preview采用对应缩略图尺寸。旧480配置无新增字段时继续读取；正式多尺寸目标须明确提供canvas，不能继承480验收。

snapshot.config追加：
- `background_id`：该目标全屏背景母件。
- `resource_ids`：本目标切图母件ID列表，含完整状态族，不含仅供编辑的依赖组件。
- `shared_master_ids`：实际引用的外部分区母件ID列表；采集器只额外读取这些母件、组件依赖和必要祖先样式，不扫描其他完整表盘。

snapshot的`export_items`仍使用原相对路径；`content_safe_ids`列出Active/AOD中需核对安全区的实际功能内容节点（按所属根换算）；`numeric_groups`列出数值自动布局组ID，检查零间距及实际切图边框相接。资源族、状态族、时间角色及指针数组按目标分别填写。背景全屏几何通过只证明尺寸，背景是否真正铺满、重新构图以及安全区清单是否完整需独立复核。

每族可追加 `export_node_ids`，列出本目标 `asset_board_id` 内实际参与正式PNG导出的母件或实例。例如 `node_ids: ["shared-zero", "local-one"]` 对应 `export_node_ids: ["local-zero-instance", "local-one"]`，其中实例的 `main_component_id` 必须为 `shared-zero`。目标板单独导出须覆盖全部已声明成员；不能因0、4、8复用外区母件而漏掉本区实例。检查真实祖先、显隐、PNG设置、唯一正式导出项、重名、重复路径及重复成员，不自动增加字符或判定字符应有多少。旧快照没有映射时记 `unverified`，旧报告保留原字节；明确空族且未见文字/字模线索时才可不适用。

每目标稳定采集、分页合并并绑定需求。共享母件及依赖必须进入签名，不能只在校验器放行外部引用。母件变化使所有依赖它的目标资源证据失效；其他目标单独改稿不应强迫未变化资源重新导出。

## 多目标检查与导出复用

新增薄入口`scripts/multisize.py`依次调用现有检查器，各目标保留独立报告。批次JSON为：

```json
{"targets":[
  {"manifest":"466/manifest.json","snapshot":"466/snapshot.json","evidence":"466/run.json"},
  {"manifest":"390/manifest.json","snapshot":"390/snapshot.json","evidence":"390/run.json"}
]}
```

路径相对批次文件。`evidence`尚未建立时可省略，相关结论为未验证。调用：

```bash
uv run --with pillow python "<SKILL_DIR>/scripts/multisize.py" batch.json \
  --exports-root exports --plan-exports --report export-plan.json
uv run --with pillow python "<SKILL_DIR>/scripts/multisize.py" batch.json \
  --exports-root exports --report multi-size-report.json
```

`--plan-exports`只规划，不调用Figma、不写切图。动作：`export`使用现有Figma工具导出并record_export；`copy`在来源完成绑定后调用`copy_shared_export(source,target,source_path,path,exports_root)`；`reuse`使用本轮仍有效文件。调用后保存各目标run，批次报告不替代原始证据。

跨目标复用要求同文件、同母件ID、同尺寸、同导出设置、完整依赖指纹相同，实际PNG存在且哈希/尺寸一致。背景、Active、AOD和展示稿不跨目标继承。共享PNG本轮只请求导出一次，再复制到目标外层目录；同名不同母件不自动共享，用户改过的目标文件不覆盖。只保留当前任务临时缓存，不新增永久缓存。

整个任务结束后调用`cleanup_batch(targets,exports_root,finished=True)`，按登记路径清理未变化PNG；提前清理会被拒绝，未登记源图及用户改变的文件保留。清理后不可继续宣称PNG仍可复用。每目标资源量和项目唯一资源量分别统计，不直接换算运行内存。

## 验证边界

用户明确不导出、改为人工验收时，停止切图及预览导出，以实际Figma画布和节点回读复核；记录未做PNG检查、用户验收待完成，不能用导出检查流程覆盖这项选择。

每个新目标检查原生尺寸画面、放大局部、最长数值、日期11/18/28/31、单位切换、进度端点、指针全周、AOD及缩略图。脚本按原始节点/PNG检查；未采集模板、安全边界或PNG则标未验证。脚本不判断背景美观、信息取舍或“95%相似”。用户视觉验收与真机验证分别记录，不继承源盘或其他尺寸的验收结论。
