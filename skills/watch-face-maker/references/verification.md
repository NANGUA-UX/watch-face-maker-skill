# 交付验证

## 视觉检查

- 指针交付核对切图区的可见位置标注：红线值为切图顶边至轴心距离；实际尺寸、局部／屏幕轴心、零位摆放与当前母件和实例一致。覆盖AOD及已有数据指针，不导出标注或将其混入正式画面，详见[指针标注](analog-pointers.md)。
- 采用噪点、纹理、玻璃或着色器时，按[效果选择与实际验证](background-composition.md)核对效果栈、参数生效、目标尺寸清晰度及下方内容依赖；只对受影响资源增量导出。区分能力存在、实际写入、视觉复核与导出通过，不将静态PNG交付误报为开发必须支持同一实时效果。
- 复杂、模糊或反馈区域按[局部还原检查](design-rationality.md)分别记录轮廓、材质分层和目标尺寸画面；核对制作方式、关键约束及选择理由，不要求直接AI路线提供原生失败证据。实际试做过才记录结果，结构检查不能识别所有错误分件，剪影通过也不能代替材质检查。
- AI素材按[质量门槛](background-composition.md#ai素材质量门槛)检查轮廓、材质、清晰度、光影、必要的透明边缘及与原生元素衔接，覆盖原始素材、目标尺寸局部和整盘。高分辨率或缩略图正常不能抵消涂抹、重影、糊斑和融化等缺陷；保留有依据的磨损、颗粒和光晕。关键项失败不得交付，未检查项标未验证；连续两轮同一问题无明确改善时停止重复当前方法，换方法或按设计取舍范围确认。检查结果须有对应画面或文件证据，不能靠清单为空或测试通过认定质量合格。
- 约95%相似按逐项视觉还原目标处理，不填写猜测分数。自动检查、代理视觉复核、用户确认和真机验证分别记录；未修正的关键形状错误不得以其他项目通过抵消。
- 先核对项目 `design-review.md`：原参考中的问题是否已按[设计合理性评审](design-rationality.md)处理，需确认的修改是否得到确认；建议、风险和已修复不得混写。复用脚本结果不替代语义、亲近性或动态可读性判断。
- 480×480 主表盘与参考图对比：构图、中心轴、留白、字号、颜色、图标语义和信息层级。
- 参考图与主表盘统一到相同像素尺寸，使用并排图或半透明叠图逐区检查锚点；不能用不同缩放比例的两张截图直接判断位置和大小。
- 背景要求贴边时，检查最外层有效图形是否到达 480×480 画框边缘，四周不得残留源图自带的黑色空边。
- 256×256 缩略图检查小尺寸可读性。
- 检查文字、官方组件实例和关键图标是否被裁切。
- 用户提出视觉修正后重新检查涉及区域及派生资源，不沿用这些区域的旧结论；已采用的纠错方案作为布局依据，保留原参考作为风格依据，不以像素相似度要求恢复原错误。

## AOD

- 主时间可见字形的位置和尺寸与亮屏稿对应；检查描边为 `#B3B3B3` 且无填充。描边后的完整边界加安全余量决定切图尺寸，不能沿用实心字的旧框导致切边。
- 用户手动调整过 AOD 时先采集现场；调整切图框后补偿实例偏移，用同尺寸前后截图核对可见字形未漂移。
- 只保留用户允许的字段。
- 使用导出的实际 PNG 统计圆形屏幕内亮像素，亮屏比例不得超过规范上限；当前默认上限为 10%。

## 结构与资源

- 数据字模先检查复用关系：同层级同字号同样式的数据不得按功能重复建立0–9母件；一档使用Num/Data，两档使用Num/Data/Large和Num/Data/Small。合并后检查实例引用、实际字符、字形位置、重复母件清除及新旧资源映射。需要保留的旧专用字模记录用户确认范围，不以资源减量为由改变未经确认的视觉层级。

- 按 [背景合并与独立切图](background-composition.md) 检查源图层及实际导出，确认必须变化的内容没有固定进背景；普通连续进度底可以合入背景，异形进度与电量状态必须带底切出。背景内部的固定元素不要求另有独立切图。
- 本次有动画时，按 [动画切图](animation-assets.md) 检查全部帧的尺寸、顺序和导出，并复核完整播放；允许固定底随帧合成，实时数据仍须独立。未验证播放时不能声称动画交付通过。
- 目标主画框 ID 和尺寸符合任务要求。
- 功能模块布局容器应包住实际子内容，不能遗留无必要的整屏范围；空的旧布局容器应清理。收紧前后比较后代绝对坐标、尺寸与母件引用，并检查Active、主稿和等比缩略图同步。整屏背景、主稿及AOD不套用此收紧规则；布局容器不自动设置切图导出。
- 动态字段都有对应状态族；极值和空/满状态可显示。
- 状态实际数量等于清单期望数量。
- `weather`、`battery`、`bluetooth` 以及各进度资源分别作为有状态能力写入 `capabilities.requested`；校验时必须存在同名状态族。天气、电池和蓝牙分别按当前规范检查 48、11、2 个状态，进度资源按本次段数检查空状态到满状态。
- 名称唯一，序列从 0 连续且无缺号；单图资源没有多余序号。
- 新字段使用 PascalCase；同一项目统一使用完整字段、缩写字段或已记录的旧项目锁定模式。
- `naming.unresolved_terms`、`mixed_paths`、`duplicate_abbreviations` 和 `non_pascal_case_fields` 均为空。
- 默认语言集合只有 `EN`；只有用户明确提出时才出现其他语言。
- 参考图复刻逐区检查外圈厚度和刻度、面板轮廓和层级、渐变与阴影、数字与标签比例、图标实心/线性重量、留白和中心焦点；仅字段齐全或布局大致相同不能判定视觉通过。
- 外圈数字沿圆周切线旋转时，要同时核对角度大小、左右镜像方向和可读朝向；仅角度绝对值相同仍可能与参考图反向。优先按圆心和固定半径定位每个数字的视觉中心，再检查 `60/30` 水平、`45/15` 竖向及其余四对斜向数字。
- 切图资源区的实际节点类型必须为 `SECTION`，不能仅凭名称判断；单个切图保持组件。主表盘、AOD、缩略图及必要的标注画框不因这条规则改为分区。
- 所有正式切图组件都有 PNG 导出设置，倍率和尺寸正确。
- 位图背景的源图分辨率与导出倍率分开验证：Figma 原始填充应保留高分辨率源文件，回读像素尺寸并在可行时核对哈希；节点的 1× 导出设置不能作为上传低分辨率源图的理由。
- 组件库图标在 Figma 源设计中保持实例关系，包括合入背景的固定图标；缺失图标使用纯色色块。
- 图标母件逐个检查可见直接子节点：组件库有对应资源时必须只有组件库实例；没有对应资源时只能有一个单一纯色色块。自绘矢量、描摹图标、组件实例上的自绘覆盖层、已有组件却改用占位块都判定失败。
- 主表盘、AOD和缩略图中的可见内容必须由有效切图实例祖先承载。展开实例后的 TEXT/VECTOR 叶子是正常内部结构；不能仅凭叶子类型判错，也不能用同名或隐藏实例证明实际显示内容已实例化。
- 展示组装实例的 `mainComponent` 必须引用本次切图板母件；母件内部的官方库实例允许引用库中母件，需记录来源并验证未断链。检查有效可见性及完整祖先链，不能把内嵌官方实例错误判为外部散件。
- 逐个文字组件检查宽高都能被 4 整除；同一资源族的高度只有一个值。
- 按原生TEXT识别所有文字切图，覆盖数字、同组符号单位、星期、月份和标签；不能仅按Num路径或0–9字符筛选。检查文本框宽高为正偶数整数、X/Y最多一位小数、完整字形无切边，字号和字形尺寸未改变。数字、词语和单位核对可见字形中心；单字符标点核对水平中心，垂直位置另对照数字基线或已确认的符号排版。中心偏差每轴不超过0.05px，另容许0.001px浮点尾差。必须回读原始节点；CENTER属性和格式化显示不能替代检查。复核星期/月与日期的基线、Active/AOD及派生实例。
- 调整多字符文本框时，先完成尺寸修改，再按未被裁切的完整字形重新定位；不能拿父框已裁过的absoluteRenderBounds计算中心。测量临时关闭裁切时，完成后恢复原裁切设置。
- 数据类和日期类只检查 `0–9` 数字在各自资源族内宽高一致；标点、符号和单位不得被数字的统一宽度规则扩大。
- 数据类和日期类还要检查统一宽度等于 `0–9` 中最大 `absoluteRenderBounds.width` 加左右安全余量后向上取整得到的最小 4 倍数；即使全族等宽，只要还能安全缩小 4 px 就判定失败。
- 用实际渲染边界检查文字四边无切边；时间数字、标点、符号和单位的宽度必须是包含安全余量后的最小 4 倍数，标点保留所属资源族的统一高度和字体基线。
- 已实现能力必须全部来自本次请求；`capabilities.unrequested_generated` 和 `excluded_generated` 均为空。配置文档第 5、6、9 点不进入默认交付。
- `capabilities.outside_boundary_requested` 和 `outside_boundary_generated` 均为空，证明设计没有把开发文档未支持的效果直接作为交付项。

## 整数定位和异形进度

- 从原始图层读取X/Y，检查主稿、Active、AOD和切图母件的可见原生布局。隐藏历史稿与组件内矢量路径不作为独立布局；实例先检查自身定位，再回到源母件检查。缩略图等比变换产生的小数不是新增布局坐标。
- 整数化后重新测字形完整边界，核对基线、主时间/AOD一致性及画面。不能仅把报告里的数值取整。
- 异形进度所有状态必须保留完整底形；检查000非透明、分段数量完整、PNG透明轮廓一致，亮起段数量逐级增加。普通前景切图的000可透明，不能把异形规则强加给所有进度。
