# 命名契约（v3.0）

本文说明附带工具的命名配置，不附带团队内部规范原文或私有Figma文件。实际项目由使用者提供可访问的命名文档、字段映射和开发确认；文档与工具配置不一致时先记录差异并适配校验器，不能假设脚本支持任意命名方案。

## 当前工具配置

- 表盘中文名为1–4个中文字符；英文名为1–12个英文字母、数字及单词间单个空格，首字母大写，不含下划线或路径分隔符。
- 新命名模式记录五位数字 `product_code`。正式名称为 `<EnglishName>/<中文名>（<五位编码>）`，英文名保留空格；切图 `prefix` 去掉英文名的空格后连写，编码不写入每个切图路径。
- 技术路径为 `<DialName>/<Type>/<Property>/[Language]/[NNN]`，省略不适用的语言和序号字段，不产生空路径段。数字字模等序列从 `000` 连续编号；单图是否需要序号按字段映射确认。
- `Type` 表达呈现方式，`Property` 表达数据含义。字段名称与缩写来自用户提供的已确认映射；完整字段和缩写模式不能混用。技术字段按PascalCase命名，已明确的缩写保持其规定格式；缩写全局唯一。
- 语言按本次需求选择，不生成固定语言套餐。月份、星期等文字长度方案在同一项目中择一，不能同时输出多套同名资源。
- `naming.mode` 为 `full` 或 `short` 时，`schema_status` 为 `confirmed`；本工具保留兼容标识 `naming.spec_source=figma-v3.0:1910:298`。它不代表已读取用户的规范或取得文件权限；实际规范来源、版本和确认依据另写入项目记录。
- 规范存在冲突时记录到 `naming.unresolved_terms` 并核实；不得把历史来源中的冲突当成每个项目必有的问题，也不得编造字段映射。
- 已交付旧项目可使用 `legacy` / `legacy_locked` 保留原路径；用户未要求迁移时不批量改名。明确迁移时同步母件、实例、配置、导出映射并核对引用和实际属性。

示例 `Sample Face/示例表盘（00001）`、`SampleFace/Num/Time/000` 仅解释格式，不是已有项目、默认产品编码或用户已选名称。详细几何、状态和迁移规则见[命名与状态](naming-and-states.md)、[名称迁移](style-naming.md)和[交付验证](verification.md)。
