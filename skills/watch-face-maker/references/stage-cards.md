# 七阶段卡片

每次只填写当前卡片。产物写入项目目录并更新 `workflow-contract.json`；没有产物证据时不得把门禁改为 `pass`。

## 1. 需求入口

**输入**：用户请求、附件、目标 Figma 节点、已有项目记忆。

**操作**：区分用户要求与附件说明；确认尺寸、屏形、语言、任务模式、来源策略和素材复用权限；记录目标节点与写入权限。多尺寸任务同时确认源尺寸和全部目标尺寸。

升级或部署Skill时先确认执行主机、实际安装路径和当前版本，再核对升级后的该路径版本；仓库提交或另一台机器更新不能作为本机已生效的证据。

**产物**：合同的 `task_mode`、`target`、`source_strategy`；一份当前有效需求清单。

**通过条件**：目标尺寸与屏形来自用户确认；素材复用权限明确；目标节点、用户授权范围及只读现场证据可用；`intake` 门禁返回 `0`。技术写权限按[项目入口](project-entry.md)独立判断，允许满足条件的首次必要制作动作，不要求预先存在成功写入回执。

**失败处理**：保持 `pending`，停止 Figma 写入、背景生成和正式切图；继续不依赖缺失事实的只读检查。

## 2. 参考契约

**输入**：参考图原文件、需求清单、设计规范、开发能力和已确认纠错项。

**操作**：计算参考图 SHA-256；列出主体、姿势、比例、位置、视角和场景关系等不变量；分开记录允许调整项与禁止内容；完成设计合理性评审。复刻生成时把原参考图直接输入工具。

将已确认的弧形排版、指针轮廓和材质主体列为保护项。局部修复绑定用户认可的高清源路径、实际像素与哈希，直接使用该源编辑；预览图和截图只用于定位问题，不能代替修复源。修正可读性或AI生成错误不授予改风格的权限。

**产物**：合同的 `reference_contract`、`design-review.md`、参考图输入记录。

**通过条件**：复刻任务的哈希和不变量非空；生成输入记录覆盖合同参考哈希；`reference` 门禁返回 `0`。

**失败处理**：缺少原图或关键语义不确定时保持 `pending`，只处理不依赖该信息的区域。

## 3. 制作路线

**输入**：参考契约、组件库、目标框架能力、切图与背景边界。

**操作**：按区域选择唯一主路线和不同的降级路线；变化进度按[开发能力、形状与颜色分流](development-capabilities.md)登记模式：纯色规则圆弧、完整圆环和直线使用 `native_continuous`，不切图；非纯色规则进度及异形、异形分段使用 `state_images`。能力未确认时记录阻塞，不自动把纯色规则进度改成切图；列出不能合入背景的元素和原因。

**产物**：合同的 `production_routes`；资源矩阵和背景拆分确认记录。

**通过条件**：所有待制作区域均有主路线与降级路线；资源模式有能力依据；来源策略允许所选路线。

**失败处理**：无法落地的效果改为能力边界内方案；影响设计目标时再向用户说明并确认。

## 4. 代表性样稿

**输入**：合同、原参考图、主路线、目标尺寸和一个关键功能区。

**操作**：复杂视觉先制作背景主体、主时间和一个关键功能区；在原素材、目标尺寸局部和整盘三个尺度检查轮廓、材质、光影、透明边缘与信息层级。

整套图标先统一系列来源、轮廓、线宽、比例与状态规则；查看由当前实际资源生成的完整接触表和目标尺寸整盘，将遗漏、风格混用与授权取舍写入 `design-review.md`。单个图标通过不能替代整族评审，也不新增自动审美评分。

**产物**：样稿、尝试记录、改进证据和样稿结论。复用视觉预检生成器，对当前样稿PNG、快照及参考图生成并排、叠图、局部图与逐项评审；这些文件不能只写文字承诺。含全屏背景时，必须同时登记1×背景PNG和background_source，完成[背景边缘证据](visual-preflight.md#背景边缘证据)；框尺寸或FILL正确不能替代有效画面覆盖。

**通过条件**：复杂视觉样稿的每项视觉结论均有实际证据且为 `pass`，然后封存：

```bash
uv run --with pillow python "<SKILL_DIR>/scripts/finalize_visual_review.py" \
  <workflow-contract.json> <样稿评审目录/visual-review.json> --stage prototype \
  --manifest <audit-manifest.json> --snapshot <样稿快照.json> --exports-dir <样稿PNG目录>
```

封存自动保存独立的合同、清单、快照、原PNG、参考与对照图副本，并在当前合同登记 `prototype_evidence`；不推进组装或生产验证。再运行统一入口的 `check --gate prototype`，返回 `0` 才能进入组装。模板或完整原生方案可有 `not_applicable` 依据；若声明样稿 `pass`，同样需要封存证据。

组装和视觉预检都必须仍为pending才能封存；已尝试但失败也不能事后补签，先退回受影响阶段。需求、参考契约或路线变化后重评。后续组装使用新的工作文件，保留封存目录；仅推进门禁状态不会使原样稿失效。

**失败处理**：同一路线连续两次无明确改善后切换登记的降级路线；降级失败则设置停止状态，不制作完整状态、AOD或多尺寸版本。

## 5. 完整组装

**输入**：已通过样稿、资源矩阵、命名方案和开发能力。

**操作**：建立切图母件、Active、AOD、缩略图和状态资源；用实例组装展示；检查名称、状态数量、导出、来源、跨族碰撞、越界和引用。按需读取指针、多尺寸或动画规则。

已有源稿适配同屏形、同长宽比时，按[比例派生](multi-size.md#同屏形比例派生)克隆原生资源，仅作必要尺寸修正；检查不授予重排、转曲或重建字模的权限。源稿的生产冲突单列，不能自动修成另一套布局。

创建或复用本次目标的外层与资源 `SECTION` 时，按[工作区分区底色](workflow.md#工作区分区底色)显式设置并回读填充。

共享母件可跨区；每个资源族用 `export_node_ids` 登记本目标切图板的完整可导出母件/实例，单独导出该板必须覆盖族 `node_ids` 的全部已声明成员。局部修复列出受影响的背景、动态前景、AOD、Preview及标注，逐项同步真实引用、裁切与定位；无影响项写明依据，不以主稿正常代替联动核对。

**产物**：Figma 母件与实例、审计清单、快照配置、状态与来源映射。

包含规则圆形刻度时，执行[圆形刻度](circular-ticks.md)的构造与检查，提供源结构回读和实际画面证据；不能仅因刻度数量正确就进入视觉预检。

**通过条件**：结构检查无失败；母件和派生实例一致；合同 `assembly` 为 `pass`。

**失败处理**：从源母件修复并重新检查受影响实例；不得用展示稿正常代替资源完整性。

## 6. 视觉预检

**输入**：原参考图、当前实现 PNG、当前合同、当前 Figma 快照、审计清单和关键区域坐标。

**操作**：用当前快照登记的 `presentation_main` 正式导出运行视觉预检生成器；查看并排图、叠图和局部图；逐条把合同不变量标为 `pass`、`fail` 或 `unverified`，并引用实际证据。全部通过后运行 `finalize_visual_review.py`，一次封存结论、更新合同哈希并将视觉门禁推进为 `pass`。

**产物**：`visual-review.json`、同尺寸并排图、半透明叠图和关键区域局部图，以及当前background_edge_review及11张边缘证据。

**通过条件**：每条不变量都有证据且为 `pass`；实现图绑定当前快照和正式导出文件；没有构图偏离、素材污染、重叠或关键不变量失败；封存后 `visual_preflight` 门禁返回 `0`。

**失败处理**：保持失败或未验证状态，返回对应制作阶段修正；不输出相似百分比，不进入正式导出。

## 7. 正式验证

**输入**：审计清单、完整稳定快照、正式 PNG、本轮导出绑定、合同和视觉预检。

**操作**：运行最终校验器，检查合同与快照哈希、素材来源、阶段、结构、PNG和视觉证据；保存报告并清理登记的临时导出。

**产物**：`report.json`；草稿评审、生产校验、用户验收和固件验证四项状态；项目记忆更新。

**通过条件**：自动检查无失败且 `production_validation` 为 `pass`。用户验收和固件验证只有取得各自真实证据后才改变状态。

**失败处理**：修复失败项后重新采集受影响证据；缺失证据记 `unverified`，不能宣称正式交付通过。
