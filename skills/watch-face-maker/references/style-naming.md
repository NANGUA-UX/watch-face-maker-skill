# 按风格命名与名称迁移

风格确定后、正式切图命名前，按造型、材质、配色、整体气质提供3组中英文候选和简短理由。用户已经指定合法名称时直接采用；候选不是正式名称，未选定前不得写入分区或资源。

- `name_zh` 为1–4个中文字符；`name_en` 为1–12个英文字母、数字及单词间单个空格。英文首字母大写，表盘英文名可以保留空格，例如 `Iron Pulse`；不使用下划线或路径分隔符。
- 不生成首尾空格、重复空格、下划线或路径分隔符。
- `prefix` 从完整 `name_en` 去掉所有空格后生成，例如 `Iron Pulse` 对应 `IronPulse`。新项目等待产品提供五位数字 `product_code` 后，正式名称和总分区名称从原始 `name_en + "/" + name_zh + "（" + product_code + "）"` 生成，保留表盘英文名中的空格。
- 前缀以后的技术字段仍按既有命名规范；三位序号等已锁定规则保持不变。
- 在目标文件各页和项目记录中查重；中文名或英文名冲突时重新提供候选，不追加编号。英文按不区分大小写检查，避免本地文件系统冲突。
- 名称定稿后保持稳定，小幅改稿不重新取名。旧项目没有中英文名称时仍可读取，不截断旧前缀。

示例：`Iron Pulse` 为10字符；产品编码为 `00001` 时，正式名称 `Iron Pulse/钢铁脉动（00001）`，切图 `IronPulse/Num/Time/000`。示例不代表用户已选名。

## 只改名称的迁移

1. 记录用户选择、目标分区、原前缀、当前有效配置；查重范围需覆盖目标文件及项目记录。排除同一项目已迁移节点，确保恢复任务不会把自身当重名。
2. 只采集目标分区，保留节点ID、父子关系、母件引用及设计属性。完整属性证据保存一次，分批写入时只核对本批，不每改10个名称就重复扫描整个分区。
3. 使用 `scripts/naming.py` 的 `validate_names` 与 `plan_rename(..., product_code="00001", chosen=True, occupied=其他项目名称)` 生成计划。`nodes` 必须已限定在目标分区；缺少产品编码或尚未选名都会拒绝生成计划。旧项目只有在显式传入 `legacy=True` 时沿用旧分区格式。
4. 按计划对节点的 `name` 赋值；只替换路径开头的 `旧前缀/`。先处理原生母件及原生实例，再读取派生实例继承结果，处理仍保留旧前缀的显式名称。不得解除实例、重建组件、修改文本内容或重排用户维护区域。
5. 分区和所有正式资源、相关实例、当前配置、导出映射同步。调用 `migrate_config` 只处理当前配置的副本，保留项目目录；不要对整个仓库全文替换，不改写历史报告、归档和Git历史。
6. 写入失败先读状态。记录每批已完成ID；恢复时以当前名称为准，已是新名称的节点跳过。迁移函数重复运行不得创建新节点或额外改名。
7. 完成后统一检查旧前缀残留、表盘英文名空格、切图前缀连写、切图路径中的空格或下划线残留、五位编码、后续字段、数量、节点ID、组件引用、布局及样式。`verify_rename` 比较原始节点记录，只允许计划中的名称变化。Figma派生几何重算若出现尾差，必须定位具体字段并记录，不能随意放宽全部属性校验或直接宣布一致。
8. 只更名不重新导出整盘，也不重复要求用户视觉验收。真实属性差异或缺失证据单独标明。

已交付旧项目的空格前缀和“中文名-英文名”分区继续标记为 `legacy_locked`，不因新规范自动迁移。文件路径使用 `pathlib.Path`，命令使用参数数组。
