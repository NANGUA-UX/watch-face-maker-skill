# 动画切图

用户明确需要动效或 PNG 帧序列时读取本文件。问「能不能做」时答可行性，评审动效时按约定的播放方式交预览，正式制作动态表盘时按下表建立母件并导出 PNG。时间、日期、实时数据和需要切换的文字、单位在整盘预览中独立叠加，导出背景帧时隐藏这些图层。

## 动态表盘交付分流

| 动画范围 | 切图资源分区中的背景资源 | 组装方式 |
| --- | --- | --- |
| 全屏动态 | 60 个全尺寸动画帧母件，各导出 1× PNG。 | 用序列覆盖已确认的整屏，必要的固定底随帧合成，无需再导出单独的静态 `Bg`。 |
| 局部动态 | 一张全尺寸静态 `<Prefix>/Bg` 的 1× PNG，加 60 个使用同一局部裁框的动画帧母件，各导出 1× PNG。 | 将局部帧按同一个 `(x, y)` 叠在 `Bg` 上。固定刻度、图案等可合并的不变内容留在 `Bg`；需要覆盖动态内容的固定前景继续按层叠关系独立。 |

两种序列的母件均命名为 `<Prefix>/Ani/000` 至 `<Prefix>/Ani/059`，对应同路径的 `.png` 文件。`Prefix` 使用英文表盘名去掉空格后的连写值，`Ani` 后直接接三位编号，不插入属性名或语言。60 帧用于正式动态背景交付，图标或独立特效动画、试制预览和已验收旧稿按各自已确认的规则处理。

## 制作前确定

- 记录动画对象、变化方式及下文的播放方案。沿用项目已确认的选择，只询问仍影响交付的缺项。
- 对照目标设备开发能力，确定帧率或每帧时长、资源数量和体积限制。正式背景序列的 60 帧不规定播放时长，帧率、触发与循环方式按项目确认。
- 分别记录 PNG 磁盘体积和运行资源估算。未压缩像素量可按宽×高×每像素字节数估算；运行内存还取决于同时驻留帧数、解码缓冲、对齐和缓存策略，未知项必须标明，不能把全部帧文件体积或简单乘积当真机内存。设备预算、像素格式或播放参数不明时可先做范围分析和试制，但不能宣布内存或播放验证通过。
- 在生成背景前确定全屏或局部动画区域。局部序列使用覆盖全部帧运动范围与效果边缘的最小安全公共裁框，记录原盘坐标。动效分散在屏幕边缘时，透明叠加的公共裁框可以与屏幕同尺寸，仍与 `Bg` 分开。全屏背景序列使用已确认的目标屏幕尺寸。
- 将动画区域及随帧合成的固定内容加入背景拆分清单，按既有流程供用户确认。实时数据和需切换的文字、单位仍保持独立。

## 从静态参考制作循环背景

1. **准备底图。** 优先用可复用的分层源稿。只有合成截图时，先移除印在图上的时间、日期、数据及其投影，用相邻天空、纹理等补齐。提取要移动的雪点或粒子后，修掉原位置的静态副本。检查没有文字残影、条带或重复雪点，再用这张底图渲染全部帧。
2. **固定时间轴。** 记录总帧数 `N`（正式动态背景 `N = 60`）、单轮时长（秒）和播放帧率。匀速序列的帧率为 `N / 时长`。循环取样用 `t = i / N`，其中 `i = 0 … N-1`。例如 2 秒共 60 帧就是 30 fps，最后一帧取在 59/30 秒；循环模式的下一帧回到第 0 帧。
3. **分别制作运动。** 只启用需求点名的效果。将底图、遮罩、运动参数及粒子随机种子和可重跑的渲染源保存在项目中，预览与正式导出共用。

   | 效果 | 每帧的做法 |
   | --- | --- |
   | 沿灯串追光 | 按参考图的走线排列灯芯中心。共 `M` 颗时，第 `j` 颗在循环相位 `j/M` 达到峰值。围绕峰值平滑提亮、衰减，并叠加同色光晕，让亮点沿线路传递。 |
   | 大灯球错峰闪烁 | 给每颗灯球独立的峰值相位。保留原色、球面高光和暗边，让灯芯和附近光晕随亮度一起变化。只改大灯时沿用已认可的小灯和粒子轨迹。 |
   | 飘雪、气泡等粒子 | 用固定种子一次生成粒子的起点、速度和相位。每帧由 `u = (t + 粒子相位) % 1` 计算位置。按方向平移，可加轻微横摆；在遮挡处或淡出后回到起点，用遮罩确定与景物的前后关系。 |

   可直接用 `((1 + cos(2π(t - 峰值相位))) / 2) ** k` 计算周期亮度，正数 `k` 越大，亮起的时间越短。飘雪可用 `y = 起点 + 下降距离 × u`，并在每条轨迹的两端把透明度平滑降到零，让雪点回到起点时自然衔接。

4. **在整盘看动效。** 将动态背景放在独立时间和数据层下，按目标帧率播放。调整用户点名的效果后，从同一套源重新生成预览；正式切图沿用认可版本的节奏、轨迹和构图。

## 母件与导出

- 每一帧在对应目标的切图资源分区内建立切图母件。局部动态的 `Bg` 母件放在同一分区；展示稿引用背景与代表帧实例。预览视频用于检查播放效果，不能替代逐帧资源。
- 同一序列使用一致的画框尺寸、裁切范围和定位基准，覆盖整个运动范围。不能逐帧单独贴边裁切导致位置跳动；动画画框不要机械套用文字切图的 4 倍数规则。
- 正式动态背景按上表配置逐帧 1× PNG 并实际导出，检查文件名、像素尺寸、透明区域和底图合成方式。其他动画沿用项目已确认的命名、数量和导出设置。

### 局部背景的正式底色

局部帧叠在 `Bg` 上时保留透明通道，让固定内容透出。只有局部区域已确认为独立显示的完整场景，且合成确实需要不透明黑底时，才按实际有效区域填充 `#000000`；项目指定其他底色则遵循已确认要求。把帧按原坐标叠回 `Bg`，核对黑边、遮挡和接缝。切图资源区的 Figma 分区底色只用于展示。

已认可的目标尺寸无损背景帧可以直接复用。只有低分辨率动图、整盘预览或有损视频时，优先回到制作源，隐藏实时信息层并按目标尺寸导出。若源已丢失，按上节从参考图重建，播放对照认可版本的节奏和轨迹，标明是重建稿。

下面的命令把一个目录内的独立透明背景 PNG 合成到黑底，保留文件名和尺寸。输入目录仅放本次序列，输出到新目录。

```bash
uv run --with pillow python - approved-frames delivery-black <<'PY'
from pathlib import Path
import sys
from PIL import Image

source, target = map(Path, sys.argv[1:])
frames = sorted(source.glob("*.png"))
if not frames:
    sys.exit("输入目录中没有 PNG 帧")
target.mkdir()
for frame in frames:
    with Image.open(frame) as image:
        rgba = image.convert("RGBA")
        black = Image.new("RGBA", rgba.size, (0, 0, 0, 255))
        Image.alpha_composite(black, rgba).convert("RGB").save(target / frame.name)
PY
```

## 预览 MP4 与开发播放说明

正式动态表盘每个目标规格同时交付 **App 展示 MP4** 和 **《表盘动画规则说明》**。用当前版本的 `Ani` 序列、静态 `Bg`（适用时）和亮屏布局合成 MP4。视频只呈现完整表盘按正常节奏播放的效果，保留目标屏形及时间、日期、数据示例。实际交付 `.mp4` 文件，在该规格的展示区放「预览 MP4」。当前工具无法嵌入视频时，在对应位置附可访问的 MP4 链接并保留文件交付。

在该规格的切图资源分区放可编辑的「表盘动画规则」文字标注，交付记录同步同一份说明。标注和 MP4 不进入切图 PNG 导出清单。正式说明按项目已确认的行为二选一，有特例时遵循项目确认：

| 方案 | 写给开发 |
| --- | --- |
| 一：亮屏播一次，点击重播 | 每次亮屏后从 `000` 播到 `059` 一次，播放结束停在已确认的画面。保持亮屏时，后续点击屏幕可从 `000` 再播一次。点击唤醒属于亮屏触发，同一次点击只启动一次播放。 |
| 二：翻腕或点击亮屏后循环 | 翻腕或点击触发亮屏后，从 `000` 播到 `059`，亮屏期间按 `059 → 000` 连续循环，熄屏时停止。 |

说明还需写明帧序、帧数、帧率或每帧时长、单轮时长、停留或循环行为，以及熄屏和 AOD 行为。局部动画附 `Bg` 路径、公共裁框尺寸和叠放坐标。方案一还需明确结束停留帧和播放中再次点击的处理方式。播放方案、节奏或关键结束行为未确认时，标出具体待确认项，播放说明先作为评审稿。MP4 验证可见效果，设备触发与播放行为由真机验证单独记录。

## 验证

- 核对切图资源分区里的实际帧母件及导出 PNG。正式背景序列必须有连续的 `Ani/000` 至 `Ani/059`，无漏帧、错序或重复名称，全部符合共同裁框和 1× 像素尺寸。
- 全屏序列检查目标屏幕尺寸和有效内容覆盖。局部动画检查同分区有一张全尺寸 `Bg`，静态内容确实合入其中，所有帧按同一坐标叠放，接缝自然且未遮掉固定内容。
- 检查首帧、变化较大的中间帧和末帧，并播放完整序列检查裁切、闪烁、边缘接缝、定位跳动和结束行为。只有要求循环时才检查循环接缝。
- 制作检查时对循环序列按实际帧率连播两轮，重点看末帧到首帧的亮度和位移是否与相邻帧连续。黑底交付抽查空白像素为 RGB `(0, 0, 0)` 且不透明，并检查半透明光晕在黑底上的过渡；透明叠加层贴回目标底色检查边缘。
- 把序列放回完整表盘，确认时间、实时数据等仍独立更新，背景没有重复留下动画对象造成重影。
- 交付 PNG 序列目录或其 ZIP、当前 App 展示 MP4 和播放说明。打包后核对实际帧路径与帧数、MP4 可播放且正常呈现当前整盘动效、播放说明与已确认方案一致。
- 按[证据契约](evidence-contract.md#figma-快照采集)填入 `features.background_animation` 和实际 `animations` 帧映射，再运行正式校验，防止用预览文件或自报帧数通过资源检查。
- AOD 按独立需求处理，不因亮屏有动画就自动在 AOD 播放。
- 缺少帧率、触发条件或设备验证时明确标为待确认，不能把静态截图或切图检查当作真机播放验收。
